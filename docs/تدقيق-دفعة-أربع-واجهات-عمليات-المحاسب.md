# تدقيق دفعة أربع واجهات عمليات المحاسب

> حالة التنفيذ: نُقلت السلوكيات العامة الآمنة في واجهات الغياب والسحب والتحصيل والمديونية إلى `ui-actions` دون تعديل العمليات المالية أو قواعد الشفتات.

## 1. تسجيل الغياب

- أصبح البحث عن الموظف يستخدم `data-ui-filter-input` و`data-ui-filter-value`.
- أصبح اختيار الموظف يجهز مسار نموذج الغياب واسمه ويفتح المودال عبر عقود البيانات.
- أصبحت الخلفية وأزرار الإغلاق تعيد ضبط النموذج وتفك قفل التمرير عبر الوحدة المشتركة.
- أصبح منع الإرسال المتكرر يستخدم `data-ui-single-submit`.

## 2. تسجيل السحب

- طُبقت عقود البحث وفتح المودال وإغلاقه وإعادة ضبطه وقفل التمرير.
- يملأ العقد المشترك اسم الموظف ومعرفه ومسار النموذج من بيانات زر الموظف.
- بقيت أسماء حقول المبلغ والتاريخ والوصف ومعرف الموظف كما هي.

## 3. واجهة تحصيل الآجل

- نُقلت تصفية الموظفين ونصوص عمليات الآجل إلى فلتر `ui-actions` المشترك.
- لم تتغير المودالات أو مبالغ التحصيل أو طرق الدفع أو طلبات التحصيل.

## 4. واجهة مديونيات المحاسب

- نُقلت تصفية الموظفين وملاحظات المديونية إلى الفلتر المشترك.
- لم تتغير المديونيات أو التحصيلات أو المبالغ أو شروط الإتاحة.

## حدود الأمان

- لم يُعدل Controller أو Route أو Model أو Migration أو Service أو استعلام.
- لم تتغير الحسابات أو المخزون أو الشفتات أو الصلاحيات أو آلية البيانات.
- لم تتغير طرق HTTP أو أسماء الحقول أو مسارات الحفظ.
- بقيت السلوكيات الخاصة بالتحصيل والمديونية في مكانها؛ المستخرج هو البحث وإدارة المودال والإرسال الأحادي فقط.

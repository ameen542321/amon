# تشغيل واختبار PWA الأساسية

## الحالة المنفذة

- Manifest عربي وRTL باسم CARLED.
- أيقونة واحدة بصيغة SVG النصية القابلة للتحجيم؛ لا توجد أيقونات PNG ثنائية.
- تشغيل `standalone` عند دعم التثبيت من المتصفح.
- Service Worker يخزن Offline shell والملفات العامة الثابتة فقط.
- صفحات ومسارات المالك والمحاسب والإدارة وAPI لا تدخل Runtime Cache.
- العمليات POST وPUT وPATCH وDELETE لا تعترض ولا تؤجل عند انقطاع الإنترنت.
- App Context محمي بجلسة المالك أو المحاسب، واستجابته `private, no-store`.
- `X-Request-ID` جديد لكل طلب لتتبع الأخطاء.
- لوحة مشتركة تعرض زر التثبيت عندما يتيحه المتصفح، وتنبه للانقطاع وعودة الاتصال.
- تحديث Service Worker لا يطبق تلقائيًا؛ يطلب من المستخدم حفظ النموذج ثم الضغط
  على «تحديث الآن» قبل إعادة تحميل الصفحة.

## التشغيل المحلي

```bash
npm install
npm run build
php artisan serve
```

افتح `http://localhost:8000` ثم DevTools → Application وافحص Manifest وService
Workers وCache Storage. بعد أول زيارة متصلة، اقطع الشبكة وافتح مسارًا جديدًا؛
يجب أن تظهر صفحة Offline العامة دون بيانات حساب محفوظة.

## فحص العقد

```bash
npm run test:pwa
```

يفشل الفحص إذا عادت أيقونتا PNG القديمتان، أو غابت أيقونة SVG، أو حاول Service
Worker تخزين مسارات التطبيق الخاصة، أو غاب ربط Manifest من القوالب الأساسية.

## ما يحدث عند انقطاع الإنترنت

- التنقل الذي يحتاج Laravel يعرض Offline shell العامة.
- لا يعرض Service Worker نسخة مخزنة من لوحة مالك أو محاسب.
- لا يرسل أو يؤجل بيعًا أو جردًا أو نقلًا أو تحصيلًا.
- لا يدعي نجاح عملية لم تصل إلى الخادم.
- مسودة الجرد المحلية الحالية مستقلة، ولا تصبح معتمدة بسبب PWA.

## ما يحدث عند عودة الإنترنت

- زر إعادة المحاولة يعيد تحميل الصفحة من Laravel.
- لا توجد مزامنة مالية تلقائية أو Outbox في هذه المرحلة.
- يستأنف API الإشعارات الجلب ضمن الجلسة الحالية.
- أي مزامنة مستقبلية تحتاج Idempotency Key وحل تعارض معتمد لكل نظام.

## التثبيت والتحديث

- لا يظهر زر التثبيت إلا بعد إطلاق المتصفح لحدث `beforeinstallprompt`.
- إخفاء رسالة التثبيت يستمر للجلسة الحالية فقط، ولا يمنع المتصفح من عرضها لاحقًا.
- عند اكتشاف نسخة جديدة يظهر تنبيه «تحديث جديد متاح» بدل تحديث الصفحة سرًا.
- لا يرسل التطبيق `SKIP_WAITING` إلا بعد ضغط المستخدم على «تحديث الآن».
- عند انقطاع الشبكة تظهر حالة واضحة تؤكد أن العمليات لم تُرسل، وعند عودتها تظهر
  رسالة مؤقتة ثم يمكن إعادة فتح الصفحة من Laravel.

## التحقق على الاستضافة

بيئة الاختبار الحالية هي `https://carled.ddns.net/`. بعد نشر الملفات وبنائها نفذ:

```bash
npm run test:pwa:deployment -- https://carled.ddns.net
npm run test:pwa:browser -- https://carled.ddns.net
curl.exe -I https://carled.ddns.net/manifest.webmanifest
curl.exe -I https://carled.ddns.net/sw.js
curl.exe -I https://carled.ddns.net/offline.html
curl.exe -I https://carled.ddns.net/carled.svg
```

الفحص الأول يجري اتصال HTTPS حقيقيًا ويتحقق من الحالة وContent-Type وManifest
وأيقونة SVG وسياسة Cache الخاصة بـService Worker. فشل الشهادة أو السلسلة أو اسم
النطاق يؤدي إلى فشل طلب Node بدل تجاوز الخطأ. كما يجلب حزمة JavaScript المنشورة
من نفس النطاق ويتأكد أن النسخة المبنية التي وصلت إلى الخادم ما زالت تحتوي عقد
تسجيل `/sw.js`؛ وبذلك يكشف نسيان `npm run build` أو نشر HTML دون حزمة التطبيق.
ويتحقق من خصائص التثبيت الحية (`id` و`scope` و`start_url` و`standalone` واللغة
والاتجاه)، ثم يجلب مسار أيقونة SVG المعلن داخل Manifest نفسه بدل افتراض مساره.

الفحص الثاني يفتح Chrome أو Edge فعليًا بوضع Headless دون مكتبات أو ملفات ثنائية
إضافية داخل المشروع، ثم يتحقق من تفعيل Service Worker ونطاقه، ومحتوى Cache
Storage، وعدم تخزين مسارات التطبيق الخاصة، وظهور Offline shell عند قطع الشبكة،
وبقاء طلبات POST دون Queue عند الانقطاع. إذا لم يكتشف المتصفح تلقائيًا على Windows:

```bash
set "CHROME_PATH=C:\Program Files\Google\Chrome\Application\chrome.exe"
npm run test:pwa:browser -- https://carled.ddns.net
```

المتطلبات:

- HTTPS صالح، باستثناء localhost في التطوير.
- جذر الويب يشير إلى `public`.
- `sw.js` متاح من جذر النطاق.
- ملف `.env` على جهاز XAMPP يحتوي `APP_URL=https://carled.ddns.net` و
  `SESSION_SECURE_COOKIE=true`، مع بقاء `SESSION_DOMAIN=null` للحصول على Cookie
  مقيدة بالمضيف ما لم توجد حاجة موثقة لمشاركتها مع نطاق فرعي.
- لا تقدم CDN نسخة قديمة طويلة العمر من `sw.js` أو Manifest.
- بعد النشر نفذ `npm run build` ثم اختبر التثبيت والانقطاع على جهاز Android حقيقي.

إذا كان HTTPS ينتهي في Reverse Proxy قبل Apache، تأكد أن Laravel يستقبل معلومات
البروتوكول الآمن من Proxy موثوق؛ لا تثق بجميع Proxies دون حصرها. وبعد تعديل `.env`
نفذ `php artisan optimize:clear` قبل إعادة الاختبار.

### أخطاء النشر التي عولجت

- الصفحة العامة `/` تستخدم `resources/views/welcome.blade.php` ولا تمر بقالب
  المصادقة أو لوحة التحكم؛ لذلك ترتبط الآن بالـManifest والأيقونة ولوحة التثبيت
  مباشرة.
- نُقلت الأيقونة النصية من `/icons/carled.svg` إلى `/carled.svg` لأن اختبار XAMPP
  أثبت أن مجلد `public/icons` لم يصل إلى النشر بينما الملفات الجذرية وصلت بنجاح.
- رُفع إصدار Cache إلى `carled-shell-v3` حتى يحذف المتصفح Cache القديم الذي كان
  يشير إلى مسار الأيقونة السابق.

### نقطة تحقق النشر الحالية

اجتازت بيئة `https://carled.ddns.net` بوابة النشر الآلية بتاريخ 2026-09-25 عبر:

```bash
npm run test:pwa:deployment -- https://carled.ddns.net
```

تحقق الفحص بنجاح من HTTPS، وربط Manifest في الصفحة الرئيسية، وContent-Type لكل
من Manifest وService Worker وصفحة Offline وأيقونة SVG، ومنع تخزين نسخة قديمة من
`sw.js`. لذلك لا تعاد معالجة مسارات الملفات أو أنواع المحتوى ما لم يفشل الفحص
نفسه بعد نشر لاحق.

الخطوة التالية هي بوابة قبول على متصفح وجهاز حقيقي، بالترتيب الآتي:

1. افتح الموقع في Chrome أو Edge وتأكد من أن Manifest لا يعرض أخطاء.
2. تأكد من أن `sw.js` في حالة `activated and running` ومن أن نطاقه `/`.
3. ثبّت التطبيق، ثم افتحه من أيقونته وتأكد من تشغيله بوضع `standalone`.
4. بعد زيارة متصلة، فعّل Offline وافتح تنقلًا جديدًا؛ يجب أن تظهر صفحة Offline
   العامة وألا تظهر نسخة مخزنة من لوحة مستخدم.
5. أعد الاتصال وتأكد من ظهور حالة عودة الاتصال ومن نجاح «إعادة المحاولة».
6. عند نشر نسخة جديدة، تأكد من ظهور تنبيه التحديث، وألا يعاد تحميل نموذج مفتوح
   قبل ضغط «تحديث الآن».
7. في شاشة جرد المحاسب فقط، تحقق من بقاء المسودة بعد إعادة التحميل، ثم تحقق من
   أن اعتمادها ما زال يتطلب اتصالًا وحفظًا صريحًا إلى Laravel.

لا تعد هذه البوابة إذنًا لإضافة Background Sync أو مزامنة مالية أو مخزنية؛ أي
توسعة من هذا النوع تحتاج موافقة مستقلة وخطة تعارض وIdempotency قبل التنفيذ.

## حدود المرحلة

- يعتمد توفر زر التثبيت المخصص على دعم المتصفح لحدث التثبيت.
- تستخدم مسودة جرد المحاسب IndexedDB محليًا لمدة أقصاها 30 يومًا، مع فصل المفتاح
  بحسب المحاسب والجلسة والتحقق من إصدار الخادم.
- لا توجد مزامنة Background Sync أو إرسال تلقائي للمسودة؛ زر الحفظ مع الإنترنت
  هو الطريق الوحيد لتثبيت الكميات في Laravel.
- لا توجد مصادقة Token لتطبيق Flutter.
- لا يوجد OneSignal Web SDK أو طلب إذن Push ضمن تأسيس PWA الحالي.
- الأيقونة SVG مقصودة لمنع إدخال ملفات ثنائية إلى حزمة Git الحالية.

## المرحلة 4A: حوكمة التخزين المحلي

- أصبحت مفاتيح مسودة الجرد مفصولة حسب نوع الحساب ومعرفه والمتجر وجلسة الجرد.
- تحمل كل مسودة `schemaVersion` ونطاق الحساب ونوعه والمتجر ونوع المسودة وإصدار
  الخادم ووقت الحفظ؛ وترفض الواجهة أي مسودة لا تطابق الحساب والمتجر الحاليين.
- ترقّي قاعدة IndexedDB السجلات القديمة إلى الإصدار الثاني، وتنقل مفاتيح الجرد
  القديمة عند أول فتح دون اعتمادها أو إرسالها إلى الخادم.
- الحد الأعلى للمسودة الواحدة 256 KiB، والحد الأعلى 50 مسودة لكل حساب؛ تحذف
  الأقدم أولًا عند تجاوز الحد، إضافة إلى تنظيف المسودات التي تجاوزت 30 يومًا.
- عند تسجيل الخروج تحذف مسودات الحساب الحالي فقط قبل إرسال نموذج الخروج، ولا
  تحذف Offline shell العامة ولا بيانات حساب آخر.
- لا تضيف هذه المرحلة Outbox أو Background Sync، ولا تغيّر منطق اعتماد الجرد أو
  المخزون؛ تبقى الكتابة في Laravel إجراءً صريحًا يتطلب اتصالًا.

## المرحلة 4B: أساس منع تكرار طلبات API

- أضيف عقد دائم لـ`Idempotency-Key` معزول حسب نوع الحساب ومعرفه.
- يبدأ التطبيق بمساري قراءة الإشعار وإخفائه للمالك والمحاسب فقط، ولا يشمل عمليات
  المال أو المخزون أو الجرد أو النقل.
- الطلب المطابق المكتمل يعيد الاستجابة الأصلية، والطلب المختلف بالمفتاح نفسه يرفض،
  والطلب المتزامن يعيد `409` بدل تنفيذ الأثر مرتين.
- تحفظ استجابات محدودة الحجم دون Cookies أو Authorization، وتحذف السجلات المنتهية
  كل ساعة بأمر صيانة محدود الدفعات.

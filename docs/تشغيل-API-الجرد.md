# تشغيل API الجرد والحفظ المرحلي

## النطاق

توفر هذه المرحلة قائمة جلسات الجرد وتفاصيلها وحفظ كميات المحاسب كمسودة خادم مرحلية. لا تتضمن إرسال النتيجة للمالك أو اعتماد الفروقات أو إنشاء حركة مخزون.

## المسارات

- `GET /api/v1/inventory-counts?store_id=1`: قائمة الجلسات المسموحة للحساب.
- `GET /api/v1/inventory-counts/{session}?store_id=1`: تفاصيل الجلسة وبنودها.
- `PATCH /api/v1/inventory-counts/{session}/draft`: حفظ مرحلي للمحاسب.

يتطلب الحفظ `inventory-counts:write` و`Idempotency-Key`، بينما تتطلب القراءة `inventory-counts:read`.

## العزل والخصوصية

- يرى المالك جلساته التابعة لمتجره فقط.
- يرى المحاسب الجلسات المسندة إليه فقط.
- لا تعاد لقطة كمية النظام إلى المحاسب.
- يستطيع المالك رؤية لقطة النظام عند توفرها للمراجعة.

## كشف التعارض

تعيد تفاصيل الجلسة الحقل `version` المشتق من `updated_at`. يجب إرسال هذه القيمة في `session_version` عند الحفظ. إذا تغيرت الجلسة بعد تنزيلها يرفض الخادم الحفظ ويطلب تحديث البيانات بدل الكتابة فوق تعديل أحدث.

## يوم العمل والأثر المخزني

يحدد الخادم يوم عمل الجرد من `ShiftLifecycleService`. يحفظ الحفظ المرحلي كمية المحاسب ولقطة النظام داخل معاملة واحدة، لكنه لا يعدل رصيد المنتج ولا ينشئ حركة مخزون. يظل الاعتماد النهائي خارج Mobile API.

## التحقق

```bash
npm run test:mobile-inventory-counts
php artisan route:list --path=api/v1/inventory-counts
```

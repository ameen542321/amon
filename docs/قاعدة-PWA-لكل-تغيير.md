# قاعدة مراجعة PWA لكل تغيير

## القرار الملزم

كل إضافة أو تعديل أو إصلاح في المشروع يمر بمراجعة أثر PWA قبل اعتماده. لا يعني ذلك تحويل كل ميزة إلى Offline؛ المطلوب هو منع كسر التثبيت، الجوال، التحديث، الأمان، عزل الحسابات، أو التدفقات Online-only.

يكتب منفذ التغيير في ملخص التسليم أحد القرارين:

- **PWA ينطبق:** مع ذكر الأثر والفحوص التي شغلت.
- **PWA لا ينطبق:** مع سبب محدد، مثل تعديل وثيقة داخلية لا تصل إلى التطبيق أو العميل.

## قائمة التحقق المختصرة

### الواجهة والجوال

- تعمل الواجهة على شاشة هاتف وباللمس دون اعتماد على hover فقط.
- لا يوجد CSS داخل Blade، وتستخدم مكونات وتوكنات الهوية المركزية.
- حالات التحميل، الخطأ، انقطاع الشبكة، والعودة للاتصال مفهومة عند ارتباط الميزة بطلب شبكي.

### الشبكة وOffline

- تحدد الميزة بوضوح هل هي: قراءة قابلة للـCache، مسودة محلية، أو Online-only.
- تبقى العمليات المالية، الاعتمادات المخزنية، الصلاحيات، والحذف الحساس Online-only.
- أي Mutation مؤهل لإعادة الإرسال يستخدم Idempotency ولا يعتمد على retry أعمى.
- لا يلتقط Service Worker صفحات خاصة أو استجابات API مصادق عليها داخل Cache عام.

### البيانات والحساب

- أي IndexedDB أو Local Storage يحمل نطاق الحساب والمتجر وإصدار المخطط عند احتوائه بيانات تشغيلية.
- تبديل الحساب وتسجيل الخروج لا يتركان مسودة أو بيانات خاصة ظاهرة للحساب التالي.
- لا تعد البيانات المحلية مصدر الحقيقة؛ Laravel والخدمات الحالية هما المصدر النهائي.

### التحديث والتشغيل

- لا يجبر Service Worker جديد المستخدم على تحديث مفاجئ قد يفقد مدخلات غير محفوظة.
- تبقى مفاتيح التعطيل وخطة الرجوع فعالة عند تغيير التسجيل أو Outbox أو التحديثات.
- أي أصل PWA جديد يراجع ضمن Manifest وService Worker وسياسة النشر عند الحاجة.

## الفحوص الدنيا

لكل تغيير:

```bash
npm run test:pwa:change-policy
npm run test:pwa
```

وتضاف بحسب الأثر:

```bash
npm run test:pwa:outbox
npm run test:pwa:controls
npm run test:pwa:deep-links
npm run test:pwa:browser -- https://staging.example.com
```

اختبارات المتصفح وStaging والأجهزة الفعلية لا تستبدلها الفحوص الثابتة. إذا لم تتوفر البيئة تسجل النتيجة `PENDING` أو تحذيرًا واضحًا.

## تعريف الانتهاء

لا يعد التغيير منتهيًا حتى:

1. يسجل قرار انطباق PWA في التسليم.
2. ينجح الحد الأدنى من الفحوص المناسبة.
3. لا يوسع Offline إلى عملية حساسة.
4. لا يكسر عزل الحساب أو سياسة Cache أو التحديث الآمن.
5. يوثق أي اختبار فعلي متبق بدل ادعاء نجاحه.

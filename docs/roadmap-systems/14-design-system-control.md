# متابعة الهوية ومركز التحكم

## المرجع الإلزامي

يبقى `docs/الهوية-البصرية-للمشروع.md` المرجع الرسمي للويب. عقد API لا يستبدله ولا يسمح بتجاوز قواعد Blade وCSS المركزي.

## النطاق المنجز

- عقد Design Tokens مشترك للويب وFlutter ذو رقم نسخة.
- الوضع المظلم هو الافتراضي، مع دعم الوضع الفاتح.
- ألوان العلامة والأسطح والنصوص والحدود والحالات مطابقة للقيم المركزية الحالية.
- عقد للخط العربي Cairo، وRTL، واللغة العربية، ومسارات الشعار والـManifest.
- بصمة SHA-256 ثابتة لمحتوى العقد و`ETag` لتحديد تغير النسخة الفعلية.
- ترشيح اختياري لإرجاع ثيم واحد عبر `theme=dark|light`.

## عقد API

- `GET /api/v1/design-system`
- `GET /api/v1/design-system?theme=dark`
- `GET /api/v1/design-system?theme=light`

يتطلب Bearer token وقدرة `design-system:read`. تعاد الاستجابة ضمن عقد API الخاص وبسياسة `private, no-store`.

## مصدر الحقيقة والتزامن

- القيم في `config/design_system.php` يجب أن تطابق متغيرات `resources/css/app.css` والـManifest.
- يفشل فحص `npm run test:design-system` إذا اختلف اللون الأساسي أو الخلفية أو الخط أو أصول الشعار.
- يستهلك Flutter أسماء Tokens الدلالية، لا أسماء ألوان عشوائية أو قيمًا مأخوذة من شاشة منفردة.

## Preview وPublish وRollback

- `preview=true`: يستطيع العميل معاينة العقد محليًا دون حفظه على الخادم.
- `publish=false`: لا يوجد مسار كتابة لتغيير الهوية.
- `rollback=false`: لا يدعى وجود رجوع قبل إنشاء مخزن نسخ وموافقة واعتماد بصري.

## ضوابط الويب

- لم يضف CSS داخل Blade ولم تعدل واجهة أو معادلة أو صلاحية تشغيلية.
- يبقى الوضع المظلم الافتراضي، ولا تضيف ألوان خارج الهوية المعتمدة.
- أي تعديل لاحق على القيم يحتاج تحديث CSS والعقد والاختبار في التغيير نفسه.

## النشر والرجوع

لا توجد Migration. يمكن الرجوع بإزالة المسار والقدرة والتهيئة، دون أثر على بيانات المستخدمين أو إعداداتهم الحالية.

## التحقق

```bash
npm run test:design-system
npm run test:visual
npm run build
```

## قرار المرحلة

العقد المشترك للقراءة والمعاينة جاهز. مركز النشر والرجوع المؤثر فعليًا مؤجل حتى اعتماد نموذج نسخ وصلاحيات ومراجعة بصرية منفصل.

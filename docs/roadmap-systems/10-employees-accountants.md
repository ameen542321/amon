# متابعة نظام الموظفين والمحاسبين

## النطاق المنجز

- دليل موظفين ومحاسبين للقراءة فقط عبر Mobile API.
- ملخص أعداد الحالات لكل متجر مصرح به.
- بحث بالاسم وترشيح بالحالة وصفحات Cursor محدودة.
- تقليل البيانات حسب الدور: المالك يرى بيانات الاتصال، والمحاسب لا يرى بيانات اتصال بقية الأفراد.
- المحاسب يرى حسابه فقط في دليل المحاسبين، بينما يستطيع قراءة دليل موظفي متجره لأغراض التشغيل.

## خارج النطاق عمدًا

- الرواتب والسلف والمديونيات والتحصيلات وتقارير الرواتب.
- إنشاء الموظف أو تعديله أو حذفه أو نقله.
- ترقية الموظف إلى محاسب أو خفضه أو تعليق الحساب.
- كلمات المرور والصلاحيات وسجل العمليات والملاحظات الداخلية.

هذه العمليات مالية أو صلاحيّة حساسة، ولا تُفتح قبل مراجعة مستقلة للمعاملات والتدقيق وIdempotency.

## عقد API

جميع المسارات تتطلب Bearer token وصلاحية `people:read` ومعامل `store_id`:

- `GET /api/v1/people/summary`
- `GET /api/v1/people/employees`
- `GET /api/v1/people/employees/{employee}`
- `GET /api/v1/people/accountants`
- `GET /api/v1/people/accountants/{accountant}`

تقبل القوائم `status` و`search` و`limit` و`cursor`. لا يحتوي هذا النطاق على أي مسار كتابة.

## الخصوصية

- لا يعيد API الراتب أو المديونية أو السلف أو الملاحظات أو سبب التعليق.
- لا يعيد البريد أو الهاتف للمحاسب عند استعراض الدليل.
- لا يستطيع المحاسب استعراض حسابات محاسبين آخرين.
- كل سجل مقيد بمتجر مرّ عبر `ApiStoreScopeService`.

## Offline

لا تخزن بيانات دليل الأفراد في Service Worker. يمكن للعميل الاحتفاظ بالاستجابة في الذاكرة أثناء الجلسة فقط، دون بيانات اتصال للمحاسب.

## التحقق

```bash
npm run test:mobile-people
php artisan route:list --path=api/v1/people
```

## قرار المرحلة

مرحلة القراءة الإدارية جاهزة للمراجعة. تبقى الكتابة والبيانات المالية مغلقة حتى اعتماد عقد منفصل وخطة تدقيق ورجوع.

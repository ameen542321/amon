# متابعة الاشتراكات والإدارة والأمن

## النطاق المنجز

- نظرة حوكمة للمالك تجمع حالة الحساب والاشتراك والخطة والحدود والاستخدام.
- سجل اشتراكات مقيد بالمالك مع Cursor Pagination.
- سجل جلسات أجهزة منقح لا يكشف token hash أو refresh token أو IP أو User-Agent.
- سجل تدقيق منقح يعرض نوع العملية والموضوع والتاريخ دون `details` أو الوصف أو بيانات الشبكة.
- مؤشرات صريحة بأن كل عمليات الكتابة الإدارية والأمنية معطلة في Mobile API.

## خارج النطاق عمدًا

- التجديد أو الإلغاء أو تغيير الخطة أو السعر أو تاريخ الانتهاء.
- تعليق الحساب أو المتجر أو المحاسب أو إعادة تنشيطه.
- تغيير الأدوار والصلاحيات والحدود أو إعدادات الأمان.
- عرض مركز قيادة الدعم التقني أو أحداث الأمان الداخلية في تطبيق المالك.

## عقد API

جميع المسارات تتطلب Bearer token وقدرة `governance:read`، وهي متاحة للمالك فقط:

- `GET /api/v1/governance/overview`
- `GET /api/v1/governance/subscriptions`
- `GET /api/v1/governance/sessions`
- `GET /api/v1/governance/audit`

تقبل القوائم `limit` حتى 100 و`cursor`.

## مصادر البيانات

- حالة الاشتراك الأساسية من `users.subscription_end_at` وطريقة `isSubscriptionActive()` الحالية.
- الاشتراك النشط والسجل من جدول `subscriptions` دون تعديل.
- الحدود من حقول المستخدم الفعلية مع رجوع إلى الخطة المرتبطة.
- الاستخدام من عدد المتاجر والمحاسبين الفعليين والنشطين.
- الجلسات من `api_access_tokens` لنوع المالك فقط.
- التدقيق من `logs` التابعة للمالك أو متاجره.

## الخصوصية والأمن

- لا تعاد كلمات مرور أو أسرار Tokens أو IP أو User-Agent أو أسباب تعليق.
- لا تعاد `details` أو أوصاف سجل التدقيق لأنها قد تتضمن بيانات تشغيلية حساسة.
- المحاسب مرفوض من جميع مسارات الحوكمة حتى لو حمل Token قدرة عامة.
- كل الاستجابات `private, no-store` ولا تخزن Offline.

## النشر والرجوع

لا توجد Migration ولا تعديل حالة. الرجوع يكون بإزالة المسارات والقدرة والأعلام دون تحويل بيانات.

## التحقق

```bash
npm run test:mobile-governance
php artisan route:list --path=api/v1/governance
```

## قرار المرحلة

أساس القراءة والتدقيق جاهز للمراجعة، وتبقى كل الإدارة الحساسة على مسارات الويب الحالية حتى اعتماد تدفق منفصل متعدد التحقق والتدقيق.

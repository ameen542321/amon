# متابعة التخزين المحلي وOutbox

## النطاق المنجز

- ترقية قاعدة IndexedDB إلى الإصدار 3 وإضافة مخزن `outbox` مستقل.
- السماح حصريًا بعملية `inventory-count-draft` عبر مسار حفظ مسودة الجرد.
- تخزين `localId` و`idempotencyKey` ونوع العملية والحساب والمتجر ونسخة الخادم والحالة والمحاولات وآخر خطأ.
- مزامنة العناصر المرتبة عند تحميل الصفحة أو عودة الاتصال.
- حالات `queued` و`sending` و`failed` و`conflict`، مع حد خمس محاولات تلقائية.
- تنظيف المسودات وOutbox معًا عند تسجيل الخروج.
- كشف التعارض باستخدام `session_version` وقفل الخادم الموجود في `InventoryCountService`.

## الحدود الأمنية

- القائمة البيضاء تقبل PUT لمسودة الجرد فقط.
- يمنع تخزين CSRF token أو Bearer token أو كلمة مرور داخل Outbox.
- الحد الأقصى 25 عنصرًا لكل حساب و256KB لكل Payload.
- يفصل `accountScope` و`storeId` بيانات الحسابات والمتاجر.
- لا يستخدم Service Worker لإعادة إرسال الطلبات الحساسة في الخلفية.

## العمليات المحظورة Offline

- البيع والتحصيل والمصروفات وإغلاق الشفت.
- قبول أو رفض النقل، واعتماد الجرد، وتعديل المخزون.
- اعتماد أو حذف طلب توريد.
- تغيير الاشتراك أو الحساب أو الصلاحيات.

## التعارض

لا يستخدم Last Write Wins. يرسل العميل نسخة الجلسة التي شاهدها؛ إذا تغيرت الجلسة يضع العنصر في `conflict` ويطلب تحديث الصفحة ومراجعة البيانات قبل إنشاء إرسال جديد.

## التحقق

```bash
npm run test:pwa:outbox
npm run test:pwa
npm run build
```

## قرار المرحلة

بوابة Outbox لمسودة الجرد مكتملة برمجيًا. يلزم اختبار متصفح فعلي على Staging لانقطاع الشبكة، وعودة الاتصال، وتبديل الحساب، والتعارض قبل توسيع القائمة البيضاء لأي مسودة أخرى.

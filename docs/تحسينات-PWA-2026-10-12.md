# تحسين موثوقية PWA وإدارة الجهاز

## السلوك الحالي

- زر «حالة التطبيق» يبين الاتصال المؤكد بالخادم وعدد الطلبات المؤجلة، ويفتح مركزًا للمزامنة والمسودات على الكمبيوتر والجوال.
- المركز يعرض نوع المسودة والمتجر والوقت والحجم التقريبي، ويسمح بتنزيل نسخة وحذف المسودة، أو حذف الطلب المحلي وإعادة محاولة الطلب الفاشل. حذف محلي لا يلغي عملًا تم في الخادم. حالات التعارض تتطلب مراجعة الجلسة ولا تعاد آليًا.
- التخزين المنظم في IndexedDB. مسودة التوريد تفصل الدور والحساب والمتجر؛ تنقل المسودة القديمة فقط إذا أثبت مفتاحها نفس النطاق. لا تصبح طلبية معتمدة ولا ترسل تلقائيًا.
- يوجد نطاق حساب نشط واحد للتخزين المحلي في المتصفح. تبديله ينظف الحساب السابق ويغلق العرض في تبويباته القديمة. الخروج يلغي النطاق أولًا، ثم ينتظر قفل المزامنة وينظف البيانات. فشل التنظيف يترك علامة إلغاء تمنع إعادة استخدامها قبل التنظيف عند العودة.
- حالة منع تكرار البيع السريع لها مفتاح حسب الحساب والمتجر. مسح المسودات من المركز يحافظ على حالة العملية المالية المعلقة. الخروج ينظفها. حظر التخزين يبقي حالة البيع في ذاكرة الصفحة ويعطل Outbox؛ لا يمنع عمل الواجهة المتصلة. حالة البيع القديمة غير المعزولة تزال، ويُطلب مراجعة سجل المبيعات قبل إعادة تسجيل عملية غير مؤكدة.
- لا تقبل المزامنة إلا مسودة جرد PUT على مسار داخلي مسموح، مع تطابق نسخة المصدر. الخادم يفحص الدور ونسخة الجلسة داخل المعاملة الموجودة.
- نجاح الحفظ يتطلب JSON صحيحًا ثم `saved=true` ومعرف جلسة مطابق ونسخة محفوظة. لا تعد صفحة HTML أو تحويل تسجيل الدخول نجاحًا.
- Web Locks يمنع المزامنة والتعديل على الطلبات من تبويبين بالتوازي. إذا لم يدعمه المتصفح تبقى الطلبات محفوظة دون إرسال، مع رسالة واضحة. الطلب المتوقف بحالة sending يستعاد بعد دقيقة بنفس مفتاح Idempotency. المحاولات محدودة بخمس تلقائيًا، ثم إعادة محاولة صريحة بنفس المفتاح.
- نجاح جلسة أخرى لا يمسح مسودة الصفحة. المسودة الأحدث من الطلب المؤجل تبقى، والمسودة المخالفة لنسخة الخادم تبقى للتنزيل والمراجعة بدل حذفها.
- التحديث ينتظر حفظ المسودات ويمنع التفعيل عند الفشل أو عند تغير الحقول أثناء التجهيز. النماذج الأخرى غير المحفوظة تمنع التحديث. التبويبات الأخرى تعرض زر تحديث ولا تعاد تلقائيًا، حتى عند تغير المتحكم.
- Service Worker يخزن shell عامة وأصولًا ثابتة محددة فقط، يحترم private/no-store، ويحد الأصل بـ2 MiB و160 مدخلًا. يبقي shell الحالية وإصدارًا سابقًا واحدًا للأصول ذات الأسماء المرقمة في التبويبات المفتوحة، ولا يحذف مخازن تطبيقات أخرى.
- نسخة PWA تجمع الإصدار المعلن وبصمة Vite manifest لمنع إعادة استعمال Cache قديمة عند نسيان تغيير المتغير.
- ثماني وحدات خاصة بالصفحات تحمل حسب وجود عقدها، قبل بدء Alpine. حزمة التطبيق الرئيسية أصبحت نحو 275 KiB بدل 351 KiB قبل الإضافة؛ الحجم النهائي يتغير مع البناء.
- إرشادات تثبيت Android وSafari، وأيقونات توافق PNG تولد من هندسة العلامة النصية أثناء npm build، مع Apple touch metadata. ملفات PNG مستثناة من Git.
- تفضيلات Push محفوظة في الخادم بحسب نوع الحساب ومعرفه: إشعارات الإدارة، رسائل الملاك والمحاسبين، وتنبيهات الأنظمة. الإرسال يستبعد أجهزة الحسابات التي كتمت النوع، ولا يحذف Inbox. تصنيف القالب من template_key أو category صريحة، والرسالة اليدوية حسب المرسل. الروابط العميقة الحالية تظل محمية بالصلاحيات.

## النشر

على بيئة النشر المصرح بها، بعد تثبيت الاعتماديات:

```bash
php artisan migrate --force
npm ci
npm run build
php artisan config:cache
php artisan queue:restart
```

تنشئ migration جدول notification_preferences فقط، ولا تغير بيانات المال أو المخزون. يجب تشغيل البناء قبل config:cache ليحسب إصدار PWA بصمة manifest الجديدة. انشر public/icons التي يولدها البناء مع public/build، ثم تحقق من HTTP 200 وimage/png للأيقونات الثلاث. يجب إعادة تشغيل العمال ليطبق إرسال Push التفضيلات الجديدة. قبل التراجع عن migration أعد كود الإرسال السابق حتى لا يطلب جدولًا حُذف.

لا توجد SDK Push جديدة في المتصفح؛ التفضيلات تحكم الأجهزة المسجلة حاليًا في النظام. تفعيل اشتراك Web Push والتسليم الحقيقي يحتاج إعداد مزود الإشعارات واختبار أجهزة فعليًا، ولا تسجل هذه المراجعة إرسالًا حقيقيًا ناجحًا.

## التحقق

```bash
npm test
npm run test:pwa:runtime-browser
vendor/bin/phpunit tests/Unit/Pwa*Test.php tests/Unit/ApiIdempotencyContractTest.php
```

- اختبارات Node تستخدم IndexedDB معزولة وتغطي الاستجابة غير الصحيحة، تأكيد الجلسة، المفتاح الثابت، التعارض، حدود المحاولات، الأقفال، تبديل الحساب، وعدم حذف Cache تطبيق آخر.
- اختبار Chromium يشغل خادمًا محليًا ببيانات اصطناعية ويستخدم أصول التطبيق وقالب PWA الحقيقيين، دون بيانات أو إشعارات إنتاج. يغطي المركز، عزل بيانات الحساب، الخطأ المعروض كنص، إعادة المحاولة، الإشعارات، وضع Offline، منع تحديث النموذج المعدل، فشل حفظ مسودة الجرد، وعدم مسحها عند نجاح جلسة أخرى. يتحقق من عدم إعادة التحميل عند controllerchange في تبويب لم يوافق على التحديث. يفحص 390 و1440 بكسل في الوضعين.
- PHP يختبر عزل الدور عند وجود جلستين، تفضيلات الإرسال، بقاء Inbox، وإرجاع تأكيد جلسة الجرد الفعلي. الاختبارات القديمة المعتمدة على base_path دون Laravel أصبحت تقرأ من جذر الاختبار مباشرةً.
- اختبار المتصفح الاصطناعي يحتاج Chromium وPHP وvendor وأصول البناء. يستخدم Chromium دون sandbox داخل الحاوية للاختبار المحلي الاصطناعي فقط، ولا يتصل بعناوين خارجية. PWA_SCREENSHOT_DIR اختياري لحفظ لقطات المراجعة، وCHROME_PATH وPHP_BINARY لاختيار الأدوات.

PWA ينطبق. تبقى HTTPS منشورة، وأجهزة Android/iPhone الحقيقية، وتسليم Push الفعلي، والأداء تحت حمل الإنتاج بحالة PENDING. اختبارات سطح المكتب ومحاكاة العرض لا تستبدلها. تبقى المبيعات والتحصيل واعتماد المخزون Online-only، وفتح صفحة خاصة جديدة أثناء الانقطاع يعرض shell عامة.

## نتيجة التحقق في البيئة الحالية

نجحت 77 حالة PHP (551 تحققًا)، و14 حالة Node، وبوابة npm test التي تجمع الهوية والبناء وفحوص PWA والإشعارات. نجح Chromium بالبيانات الاصطناعية والحالات المذكورة أعلاه. لم تُشغّل أي رسائل Push حقيقية ولم يُنشر التغيير إلى خادم إنتاج من هذه البيئة.

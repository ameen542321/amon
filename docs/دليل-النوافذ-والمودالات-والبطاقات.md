# دليل النوافذ والمودالات والبطاقات

> هذا المستند دليل تنفيذي مختصر مشتق من المرجع الإلزامي
> [`الهوية-البصرية-للمشروع.md`](./الهوية-البصرية-للمشروع.md). عند التعارض يكون مرجع الهوية
> البصرية هو الحاكم. لا يغيّر هذا الدليل ألوان الهوية أو منطق العمليات، وإنما يوضح طريقة
> تطبيق المكونات المعتمدة حاليًا.

## 1. الهدف

توحيد شكل النوافذ والمودالات والبطاقات في المشروع، ومنع إنشاء تصميم مختلف داخل كل صفحة،
مع الحفاظ على:

- الوضع المظلم بوصفه الوضع الافتراضي.
- الوضع الفاتح بتباين وحدود وظلال واضحة.
- سهولة الاستخدام على الجوال وشاشات اللمس.
- إمكانية الوصول بلوحة المفاتيح وقارئات الشاشة.
- فصل الهيكل في Blade عن الشكل الموجود في CSS المركزي.

## 2. المرجع البصري المعتمد للنوافذ

نافذة المساعدة في إنشاء النقل المخزني هي المرجع البصري المركزي للنوافذ التطبيقية:

- تعتيم أسود خلف النافذة بنسبة `70%`.
- تمركز النافذة أفقيًا وعموديًا داخل الشاشة.
- هامش آمن `1rem` عن حواف الشاشة.
- سطح النافذة `--ui-surface-muted`.
- نص النافذة `--ui-text`، والنص الثانوي `--ui-text-soft` أو `--ui-text-muted` بحسب أهميته.
- حد بسماكة `1px` ولون `--ui-border`.
- استدارة `1rem`.
- ظل ارتفاع مركزي: `0 25px 50px -12px rgba(0, 0, 0, .25)`.
- ارتفاع أقصى يساوي ارتفاع الشاشة ناقص `2rem`، مع تمرير صندوق النافذة كاملًا عند الحاجة.

الكلاسات المركزية التي تحقق ذلك هي:

| الدور | الكلاس |
| --- | --- |
| تعتيم وتمركز المودال | `ui-modal-backdrop` |
| صندوق المودال القياسي | `ui-modal-panel` |
| مودال التفاصيل أو الجداول الواسعة | `ui-modal-panel-wide` |
| غلاف مطابق لنافذة النقل المرجعية | `ui-modal-panel-transfer` |
| رأس المودال | `ui-modal-header` |
| نافذة المساعدة العامة | `ui-help-modal-backdrop`, `ui-help-modal-panel` |

## 3. أحجام المودالات

### 3.1 المودال القياسي

- العرض: `min(100%, 34rem)`.
- يستخدم للنماذج القصيرة، التأكيدات، وإدخال عملية واحدة.
- يمكن استخدام غلاف النقل المرجعي ليصبح الحد الأقصى `32rem`.

### 3.2 المودال الواسع

- العرض: `min(100%, 64rem)`.
- يستخدم فقط للتفاصيل الكثيرة أو البيانات الجدولية التي لا تناسب العرض القياسي.
- لا يعفي العرض الواسع من توفير تخطيط مناسب للجوال.

### 3.3 نافذة المساعدة

- العرض الأقصى `32rem`.
- محتواها مختصر ومتمركز أفقيًا.
- لا تتحول إلى صفحة شرح طويلة؛ الشرح الطويل ينقل إلى صفحة أو يقسم إلى أقسام واضحة.

## 4. بناء المودال

يتكون المودال من قطعة واحدة متصلة بصريًا:

1. **الخلفية المعتمة:** تمنع تشتيت المستخدم بمحتوى الصفحة الخلفية.
2. **الرأس:** عنوان واضح وزر إغلاق.
3. **الجسم:** البيانات أو الحقول، بمسافات متوازنة.
4. **الإجراءات:** زر رئيسي واحد عند الإمكان، وبجواره إلغاء أو رجوع بدور ثانوي واضح.

لا يعتمد هيدر `sticky` منفصلًا عن جسم المودال، ولا يعطى الرأس لونًا أو سطحًا مختلفًا. عند
زيادة المحتوى يتحرك الرأس مع الجسم ويكون التمرير على صندوق المودال كاملًا.

## 5. الرأس وزر الإغلاق

- يستخدم الرأس `ui-modal-header`.
- العنوان واضح، متوسط بصريًا، ويستخدم مرتبة عنوان المشروع.
- زر الإغلاق الأيقوني يظهر في أقصى اليسار، حتى في الواجهة العربية.
- زر `X` مربع ثابت، ومحتواه متوسط أفقيًا وعموديًا، وله `aria-label="إغلاق"`.
- زر الإغلاق الأيقوني العام يستخدم السطح الهادئ والحد المركزي، ولا يلون عشوائيًا.
- زر الإغلاق النصي الذي يمثل إلغاءً أو إجراء خطر يستخدم الدور المركزي المناسب مثل
  `ui-modal-close-text-danger` أو `ui-btn-danger`.
- نافذة المساعدة لها استثناء موثق: زر هادئ بأبعاد `2.25rem` واستدارة `.75rem`.

## 6. السلوك وإمكانية الوصول

كل مودال جديد أو مراجع يجب أن يحقق الآتي:

- `role="dialog"` و`aria-modal="true"`.
- ربط العنوان عبر `aria-labelledby` متى وجد عنوان ظاهر.
- اسم وصول واضح لكل زر أيقوني.
- إمكانية الإغلاق بالطريقة المعلنة دون الاعتماد على النقر خارج النافذة وحده.
- منع تجاوز المحتوى ارتفاع الشاشة.
- عدم إخفاء إجراء مهم خلف `hover`.
- بقاء الأزرار والحقول بمقاسات مناسبة للمس.
- استخدام SweetAlert للتنبيهات والتأكيدات التفاعلية العامة حسب مرجع الهوية، وعدم بناء
  نافذة تأكيد جديدة لكل صفحة.

## 7. الألوان والأزرار داخل المودال

- تستخدم الأسطح والنصوص والحدود متغيرات `--ui-*` فقط.
- يمنع اختيار لون مباشر داخل Blade.
- الإجراء الأساسي العام: `ui-btn ui-btn-primary`.
- التأكيد الناجح: `ui-btn ui-btn-success`.
- الرجوع أو العرض: `ui-btn ui-btn-secondary`.
- الحذف أو الإجراء المؤذي: `ui-btn ui-btn-danger`.
- التحذير التشغيلي: `ui-btn ui-btn-warning`.
- لا يوضع أكثر من زر أساسي داخل المجموعة البصرية نفسها إلا لسبب تشغيلي واضح.
- صياغة التأكيد المالي أو الحذف تذكر أثر الإجراء مباشرة، ولا تعتمد على عبارات مبهمة.

## 8. البطاقات المعتمدة

### 8.1 البطاقة الرئيسية

تستخدم `ui-card` أو المكوّن `x-ui.card`. شكلها المركزي الحالي:

- سطح `--ui-surface`.
- نص `--ui-text`.
- حد `1px` بلون `--ui-border`.
- استدارة `1rem`.
- ظل هادئ يوضح ارتفاع البطاقة عن خلفية الصفحة.
- مسافة داخلية افتراضية `p-5`، مع `p-4` للصغيرة و`p-6` للكبيرة عبر خيار المكوّن.

### 8.2 البطاقة الثانوية

تستخدم `ui-card-muted` للمناطق الداخلية أو الثانوية. لا تعامل كل حاوية داخل بطاقة رئيسية
كبطاقة مرتفعة جديدة؛ يكفي السطح الثانوي والحد غالبًا حتى لا تتراكم الظلال.

### 8.3 قواعد الاستخدام

- البطاقة تجمع معلومات أو إجراءً مترابطًا، ولا تستخدم كزخرفة.
- لا توضع خلفية مستقلة وراء عنوان البطاقة.
- لا تلون البطاقة كاملة بلون حالة إلا إذا كانت بطاقة حالة فعلية.
- الحدود أساسية في الوضع المظلم، ولا يستعاض عنها بالظل.
- تستخدم كلاسات التخطيط غير اللونية للمسافات، ولا تكتب قواعد CSS داخل Blade.

## 9. قرار الظلال المقترح للبطاقات

اعتماد الظلال على **كل البطاقات الرئيسية** مناسب، وهو متوافق أصلًا مع تعريف `ui-card`
المركزي الحالي في الوضعين. لكنه لا يعني إضافة `shadow-lg` أو `shadow-2xl` يدويًا إلى كل
عنصر في Blade.

القاعدة المقترحة للاعتماد:

1. كل بطاقة رئيسية تستخدم `ui-card` وترث الظل المركزي تلقائيًا.
2. البطاقة الثانوية أو المنطقة المتداخلة تستخدم `ui-card-muted` بلا ظل قوي افتراضيًا.
3. المودال يحتفظ بظل أعلى من البطاقة لأنه أقرب للمستخدم في طبقات الواجهة.
4. يمنع اختلاف الظلال صفحةً عن أخرى عبر كلاسات Tailwind المحلية؛ أي تعديل يكون في CSS
   المركزي وبعد فحص الوضعين.
5. في الوضع الفاتح يكون الظل هادئًا للفصل عن خلفية الصفحة، وفي الوضع المظلم يجمع مع حد
   واضح ولا يكون وسيلة الفصل الوحيدة.

بهذا نأخذ وضوح بطاقات صفحة الشفتات ونعممه من خلال المكوّن المركزي، من دون جعل كل صف أو
حقل أو بطاقة داخلية يبدو عائمًا، ومن دون خلق تفاوت بصري بين الصفحات.

## 10. مثال هيكلي معتمد

```blade
<div class="ui-modal-backdrop" role="dialog" aria-modal="true" aria-labelledby="example-title">
    <section class="ui-modal-panel ui-modal-panel-transfer">
        <header class="ui-modal-header">
            <h2 id="example-title" class="ui-title">عنوان النافذة</h2>
            <button type="button" class="ui-modal-close-danger" aria-label="إغلاق">×</button>
        </header>

        <div class="p-5">
            <p class="ui-text-soft">محتوى النافذة.</p>
        </div>

        <div class="ui-modal-actions">
            <button type="button" class="ui-btn ui-btn-secondary">رجوع</button>
            <button type="submit" class="ui-btn ui-btn-primary">حفظ</button>
        </div>
    </section>
</div>
```

المثال يوضح الهيكل والكلاسات فقط. الإظهار والإخفاء وإدارة التركيز يجب أن تستخدم آلية
JavaScript المركزية المعتمدة في المشروع، لا `element.style` داخل Blade.

## 11. قائمة مراجعة سريعة

- [ ] استخدمت الكلاسات المركزية ولم أضف CSS داخل Blade.
- [ ] النافذة واضحة في الوضعين المظلم والفاتح.
- [ ] العنوان وزر الإغلاق واضحان ومتوسطان بصريًا.
- [ ] زر الإغلاق الأيقوني يحمل `aria-label`.
- [ ] المحتوى الطويل قابل للتمرير ضمن ارتفاع الشاشة.
- [ ] يوجد زر أساسي واحد فقط في مجموعة الإجراءات عند الإمكان.
- [ ] ألوان الأزرار تطابق أدوار العمليات المعتمدة.
- [ ] البطاقة الرئيسية تستخدم `ui-card` بدل ظل محلي.
- [ ] البطاقة الثانوية لا تحمل ظلًا قويًا دون حاجة.
- [ ] اختُبرت الواجهة على الجوال وباستخدام لوحة المفاتيح.

## 12. حدود هذا المستند

هذا الدليل لا يجيز تعديل منطق مالي أو مخزني أو حسابي أو صلاحيات. إذا احتاج المودال إلى
تغيير نتيجة عملية، أو تسجيل حركة مخزون، أو تعديل تقرير، فيفصل التعديل المنطقي ويعرض أثره
ومخاطره على صاحب المشروع قبل التنفيذ.

# تدقيق ثلاثة أنظمة: قالب لوحة التحكم والثيم وبطاقات الإحصاء

> حالة التنفيذ: طُبقت إصلاحات الأنظمة الثلاثة وحُميت بعقود الفحص الآلي.

## 1. قالب الهيدر القديم

- كان `resources/views/dashboard/header.blade.php` قالب HTML كاملًا داخل ملف اسمه Header، ويحمل Alpine من CDN وصورًا ومسارات تجريبية وروابط `#` وبيانات إشعارات وهمية.
- لم يكن الملف مستدعى من أي View أو Controller؛ الهيدرات الفعلية هي `dashboard.navbars.*` داخل `dashboard.app`.
- حُذف الملف غير المستخدم بالكامل بدل إبقاء نسخة واجهة قديمة يمكن أن تعيد Alpine المكرر أو بيانات تجريبية مستقبلًا.
- لم تتغير واجهات الإشعارات الفعلية أو روابطها أو بياناتها بهذا الحذف.

## 2. نظام الثيم

- نُقل كود تهيئة الثيم المبكر من `<script>` داخل Blade إلى `public/js/dashboard-theme.js`، ويبقى تحميله متزامنًا في `<head>` لمنع ظهور الوضع الخاطئ قبل رسم الصفحة.
- وُحد تبديل الثيم للمالك والمحاسب عبر `data-theme-toggle` ووحدة `dashboard-navigation.js` بدل وجود منطق Alpine للمالك وسطر JavaScript طويل داخل زر المحاسب.
- الوحدة تحدث `dark` و`light`، وتحفظ الاختيار نفسه في `localStorage`، وتحدث `aria-pressed` لكل أزرار الثيم.
- لم تتغير قيمة مفتاح التخزين `theme` أو القيمتان `dark` و`light`.

## 3. بطاقات الإحصاء

- كان مستخدمو `x-stat-card` يمررون `value-id` لتحديث قيم اليوم، لكن المكوّن لم يعرّف الخاصية ولم يطبع المعرّف؛ لذلك لم يجد JavaScript العناصر المستهدفة.
- أضيفت خاصية `valueId`، ويطبع المكوّن `id` على عنصر القيمة فقط عند تمريرها.
- أصبح المكوّن يدمج بقية attributes على البطاقة الأساسية بدل إسقاطها.
- لم تتغير القيم المالية أو ألوان الحالات أو دوال التحديث أو مصادر البيانات.

## حدود الأمان

- لم يُعدل Controller أو Service أو Model أو استعلام أو عملية حسابية.
- لم تُعدل نواة الإشعارات أو OneSignal أو مستند قراراتها.
- لم يُضف CSS أو لون أو مكتبة خارجية.

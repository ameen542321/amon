# نطاق التنفيذ الحالي: PWA أولًا

## القرار

اعتبارًا من 2026-09-26، لا يتضمن النطاق الحالي إنشاء تطبيق Flutter. الهدف هو إكمال PWA وتشغيلها بأمان، مع إبقاء Backend جاهزًا لعميل Flutter مستقبلي دون ربط إطلاق PWA به.

## داخل النطاق الآن

1. إغلاق بوابات PWA على Chrome/Android وبيئة Staging ببيانات مصطنعة.
2. اختبار التثبيت والتحديث والانقطاع وعودة الاتصال وتبديل الحساب.
3. اختبار Outbox لمسودة الجرد والتعارض وعدم تكرار الإرسال.
4. إكمال Deep links للإشعارات داخل PWA واختبار Push الحقيقي.
5. قياس p95 والأخطاء وحجم الحزمة وQueue lag ووضع SLOs قبل الإطلاق.
6. إطلاق PWA تدريجيًا خلف أدوات تعطيل ورجوع واضحة.

## تأسيس Flutter للمستقبل

يسمح فقط بالأعمال المشتركة التي تفيد PWA والخادم الآن:

- API v1 مستقر وموثق.
- Bearer sessions قابلة للإبطال ومقيدة بالقدرات.
- أكواد أخطاء واستجابات موحدة وIdempotency للعمليات المؤهلة.
- Design Tokens دلالية ذات نسخة.
- خدمات Laravel هي المصدر الوحيد لمنطق العمل.
- توثيق عقود Offline والخصوصية والأجهزة.

لا ينشأ حاليًا `pubspec.yaml` أو ملف Dart أو مشروع Flutter أو Pipeline لبناء APK/IPA.

## خارج النطاق الآن

- واجهات Flutter وState management وSQLite الخاصة به.
- APK وIPA ومتاجر التطبيقات.
- Push وDeep links الخاصة بتطبيق Flutter.
- Pilot أو إطلاق Flutter.
- أي Offline لعملية مالية أو اعتماد مخزني.

## تعريف اكتمال PWA

تعد PWA مكتملة للإطلاق عندما:

- تنجح رحلات التثبيت والتحديث وOffline shell على أجهزة Android فعلية.
- تثبت اختبارات Staging أن المسودة لا تضيع ولا تتكرر ولا تتسرب بين الحسابات.
- تنجح الإشعارات والروابط العميقة ضمن صلاحيات المستخدم والمتجر.
- توثق SLOs وتنجح اختبارات الأداء والحمل المتفق عليها.
- تتوفر Feature flags أو Kill switch وخطة Rollback ومراقبة تشغيلية.
- ينجح Pilot محدود دون فروقات بيانات.

إكمال هذه الشروط لا يتطلب وجود تطبيق Flutter.

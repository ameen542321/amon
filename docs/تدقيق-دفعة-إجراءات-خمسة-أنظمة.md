# تدقيق دفعة إجراءات خمسة أنظمة

> حالة التنفيذ: نُقلت إجراءات واجهة متكررة من خصائص الأحداث المضمّنة في Blade إلى وحدة `ui-actions` المشتركة، دون تغيير طلبات الخادم أو البيانات.

## 1. نماذج عمليات الموظف المشتركة

- أصبحت أزرار إغلاق مودالات الغياب والسحب والمديونية تستخدم `data-ui-hide`.
- أصبحت حقول التاريخ المرئية تتزامن مع حقول التاريخ الأصلية عبر `data-ui-sync-value`.
- أزيل استدعاء `showPicker` من حقل نصي لم يكن يملك واجهة منتقي أصلًا، مع بقاء حقل التاريخ الشفاف المسؤول عن الاختيار.

## 2. شاشة إجراءات الموظف

- أصبحت مودالات ملخص الغياب والسحب والمديونية والأجل تفتح عبر `data-ui-show`.
- يحافظ `data-ui-reset-details` على السلوك السابق بإغلاق عناصر `details` المفتوحة قبل عرض المودال.
- أصبح مودال ترقية الموظف يستخدم عقود العرض والإخفاء المشتركة.

## 3. قائمة الفواتير

- استُبدل النموذج المخفي ودالة `confirmDelete` بنموذج حذف مستقل لكل فاتورة.
- يستخدم كل نموذج `data-ui-confirm` ويحافظ على `CSRF` وطريقة `DELETE` والمسار الأصلي.
- لم يتغير قرار السماح بالحذف أو المبلغ أو محتوى الفاتورة.

## 4. طباعة الفواتير والبيع السريع

- أصبحت أزرار طباعة الفاتورة وأزرار طباعة فاتورة البيع السريع تستخدم `data-ui-print`.
- بقي استدعاء الطباعة نفسه `window.print()` داخل الوحدة المشتركة، ولم يتغير قالب الطباعة أو بياناته.

## 5. مودالات مصروفات المحاسب

- أصبح فتح مودال الإضافة وإغلاق مودالي الإضافة والتعديل يستخدم `data-ui-show` و`data-ui-hide`.
- أصبح تجهيز بيانات نموذج التعديل ومساره يستخدم `data-ui-edit-form` و`data-ui-fill` مع إبقاء قالب المسار والحقول نفسها.

## حدود الأمان

- لم يُعدل Controller أو Route أو Model أو Migration أو Service أو استعلام.
- لم تتغير الحسابات المالية أو المخزون أو الصلاحيات أو آلية قراءة وكتابة البيانات.
- لم تتغير أسماء الحقول أو طرق HTTP أو المسارات.
- التغيير محصور في ربط عناصر الواجهة بوحدة JavaScript مشتركة محملة أصلًا من `app.js`.

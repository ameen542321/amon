# تدقيق نظامي فحص الأجل والمديونية

## 1. النطاق

- Health Check لبيانات البيع الآجل وتحصيلاته.
- Health Check لبيانات المديونيات وتحصيلاتها.
- صفحات الأدمن للقراءة والتشخيص فقط.

## 2. الدمج والتنظيف

- دمج هيدر الفحص وإجمالي المشاكل وبطاقات الانتقال إلى النتائج في مكوّن واحد `components/admin/health-overview.blade.php`.
- بقي كل نظام مسؤولًا عن جدوله وحقوله وتفاصيل نتائجه المختلفة.
- حذف متغيرات `cardClass` و`count` و`isDangerCard` المكررة من الواجهتين، واستبدلت بأسماء واضحة داخل المكوّن.
- حذف شرط الحد المتطابق الذي كان يعيد `ui-border` في الحالتين.
- أبقيت متغير `rows` لأنه مستخدم فعليًا في التكرار وعدد النتائج.
- لم ينشأ JavaScript أو CSS جديد، ولا توجد أحداث أو سكربتات مضمنة.

## 3. التجاوب والعرض

- أصبح عنوان الفحص وإجمالي المشاكل عموديين ومتوسطي المحاذاة على الجوال، ثم يعودان إلى صف على الشاشات الأكبر.
- أصبح إجمالي المشاكل بعرض كامل على الجوال.
- بطاقات الملخص عمود واحد ثم عمودان، وتحتفظ صفحة الأجل بأربعة أعمدة والمديونية بثلاثة على الشاشات الواسعة.
- أضيف padding أفقي آمن للصفحتين.
- حدد حد أدنى لجداول النتائج داخل حاويات التمرير، كي يبقى التمرير داخل الجدول لا الصفحة.
- رُفعت النصوص التشغيلية المهمة من النص الهادئ إلى `ui-text-soft` حيث يلزم.

## 4. حماية البيانات

- لم تتغير Controllers أو الاستعلامات أو مفاتيح `issues` أو `summary` أو `rows`.
- لم تتغير أي معادلة أو مبلغ أو حالة أو نتيجة فحص.
- لم يضف أي زر إصلاح أو حذف أو تعديل.
- لم تتغير Routes أو الصلاحيات أو قاعدة البيانات.
- لم يعدل ملف الهوية البصرية أو `resources/css/app.css`.

## 5. مراجعة القبول

1. مقارنة إجمالي المشاكل وعدد كل بطاقة قبل وبعد الإصلاح.
2. مقارنة كل صف ومبلغ وحالة في النظامين دون تنفيذ كتابة.
3. فتح روابط بطاقات الملخص والتأكد من الوصول إلى القسم المطابق.
4. مراجعة الجداول على 320 و375 و768 و1366 بكسل.
5. التأكد أن التمرير الأفقي محصور داخل الجدول.
6. مراجعة حالات: لا توجد مشاكل، تحذير، وخطر في الوضعين المظلم والفاتح.

# تشغيل API كتالوج المنتجات للأجهزة

## النطاق

هذه الحزمة تقدم كتالوجًا **للقراءة فقط** إلى PWA وFlutter. لا تنشئ بيعًا، ولا
تعدل كمية أو سعرًا، ولا تنفذ حركة مخزون. كل طلب يمر عبر Bearer Token وAbility
`catalog:read` ثم يعزل البيانات على متجر يملكه الحساب أو متجر المحاسب نفسه.

لا يعيد العقد تكلفة المنتج `cost_price` أو أي بيانات موردين. السعر والرصيد يعادان
كنصوص عشرية ثابتة حتى لا يفقد عميل الهاتف الدقة بسبب Floating Point.

## المسارات

| المسار | الغرض |
| --- | --- |
| `GET /api/v1/catalog/categories` | الأقسام النشطة وعدد المنتجات القابلة للبيع |
| `GET /api/v1/catalog/products` | قائمة وبحث وفلترة المنتجات |
| `GET /api/v1/catalog/products/{id}` | منتج واحد ضمن المتجر المسموح |
| `GET /api/v1/catalog/sync` | تغييرات محدودة زمنيًا مع سجلات الحذف |

جميع المسارات تتطلب:

```http
Authorization: Bearer carled_...
Accept: application/json
```

## اختيار المتجر وعزله

`store_id` مطلوب في كل طلب. المالك لا يستطيع قراءة إلا متجر نشط تابع له، والمحاسب
لا يستطيع تمرير متجر غير متجره. يعاد `404 NOT_FOUND` بدل كشف وجود متجر أو منتج
خارج النطاق.

## القائمة والبحث

مثال:

```http
GET /api/v1/catalog/products?store_id=12&q=زيت&category_id=4&limit=25
```

الفلاتر:

- `q`: بحث في الاسم والوصف، ومطابقة الباركود.
- `barcode`: مطابقة باركود كاملة ومناسبة للماسح.
- `category_id`: قسم داخل المتجر المحدد.
- `low_stock=1`: المنتجات التي بلغت حد المخزون وفق منطق المنتج الحالي.
- `limit`: من 1 إلى 50، والافتراضي 25.
- `cursor`: المؤشر المعاد في `meta.next_cursor`.

لا يعتمد العميل رقم صفحة؛ يرسل `next_cursor` كما هو. عند غيابه تكون القائمة قد
انتهت.

## شكل المنتج

يتضمن العقد الهوية، القسم، الاسم، الوصف، الباركود، الحالة، السعر، الرصيد، الحد
الأدنى، نوع المنتج، بيانات الوحدة وخيارات الكسور، رابط الصورة، ونسخة `updated_at`. لا يتضمن
التكلفة. حقول الأرقام المالية والمخزنية نصوص عشرية مثل `"15.00"` و`"2.500000"`.

## المزامنة التزايدية

بعد تنزيل الكتالوج الكامل يحفظ العميل آخر `watermark` ناجحًا. طلب المزامنة:

```http
GET /api/v1/catalog/sync?store_id=12&since=2026-09-25T08:00:00Z&limit=100
```

أول استجابة تعيد:

- `meta.watermark`: نهاية ثابتة لنافذة المزامنة.
- `meta.next_product_cursor`: مؤشر صفحة المنتجات التالية.
- `meta.next_category_cursor`: مؤشر صفحة الأقسام التالية.
- `data.products` و`data.categories` بما فيها `deleted_at` كسجل حذف Tombstone.

إذا بقي أي مؤشر، يكرر العميل الطلب بالقيمة نفسها لـ`since` و`until` مساوية
لـ`watermark`، ويرسل مؤشري النوعين بصورة مستقلة. لا يعتمد الـwatermark الجديد
حتى ينتهي المؤشران بنجاح.

النافذة القصوى 31 يومًا. يعيد الخادم `FULL_SYNC_REQUIRED` إذا كان العميل أقدم؛
حينها يمسح نسخة الكتالوج المحلية فقط وينزل القائمة الكاملة، دون لمس مسودات
المستخدم المحلية.

## الفهارس والأداء

Migration `2026_09_25_000005_add_mobile_catalog_indexes.php` تضيف فهارس للمتجر
والحالة والقسم والباركود و`updated_at`. بعد النشر:

```bash
php artisan migrate --force
php artisan optimize:clear
npm run test:mobile-catalog
```

راقب زمن استجابة البحث وعدد الاستعلامات وحجم صفحات المزامنة. لا ترفع الحد الأقصى
قبل قياس حقيقي على بيانات الإنتاج.

## بوابة القبول

1. مالك بمتجرين يرى متجرًا واحدًا فقط عند كل `store_id`.
2. محاسب يقرأ متجره ويرفض متجرًا آخر بـ404.
3. المنتج المحذوف أو غير النشط لا يظهر في القائمة العادية.
4. نتيجة البحث لا تحتوي `cost_price`.
5. قراءة باركود تعيد المنتج الصحيح داخل المتجر فقط.
6. Cursor لا يكرر أو يسقط عنصرًا في بيانات ثابتة.
7. المزامنة تعيد التعديل والحذف، وتثبت `watermark` عبر جميع الصفحات.
8. نافذة أقدم من 31 يومًا تعيد `FULL_SYNC_REQUIRED`.
9. لا توجد مسارات POST/PATCH/DELETE للمنتجات ضمن API الهاتف.

## الرجوع

يمكن تعطيل ميزة الكتالوج من `app-config` أولًا، ثم إزالة مسارات `catalog` مؤقتًا.
الفهارس توسعية ولا تغير البيانات ويمكن إبقاؤها عند الرجوع. لا تسقطها أثناء ضغط
تشغيلي إلا بعد مراجعة خطة الاستعلامات.

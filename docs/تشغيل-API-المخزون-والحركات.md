# تشغيل API المخزون وحركاته

## النطاق الآمن

توفر هذه المرحلة قراءة معزولة حسب المتجر ولا تضيف أي مسار لتعديل الرصيد. جميع
المسارات تتطلب Bearer Token و`inventory:read` و`store_id` مصرحًا:

- `GET /api/v1/inventory/summary`: عدد المنتجات، المنخفض والسالب، وحركات اليوم.
- `GET /api/v1/inventory/movements`: سجل الحركات مع Cursor وفلاتر المنتج والنوع ويوم العمل.
- `GET /api/v1/inventory/integrity`: فحص الرصيد السالب، الحركات ناقصة الأرصدة، ومطابقة آخر رصيد مع المنتج.

لا يعيد سجل الهاتف لقطة تكلفة المنتج. يعيد الكميات والأرصدة كنصوص عشرية ثابتة،
ويعتمد اسم المنتج والوحدة المحفوظين وقت الحركة حتى لا يغير تعديل المنتج التاريخ.

## الفلاتر

`movements` يقبل `product_id` و`type=increase|decrease` و`from` و`to` و`limit`
من 1 إلى 100 و`cursor`. يجب التعامل مع `business_date` كيوم العمل، بينما
`created_at` وقت التدقيق التقني.

## تفسير فحص السلامة

- `negative_products`: رصيد منتج أقل من صفر.
- `movements_missing_balances`: حركة لا تحتوي الرصيد السابق أو اللاحق.
- `latest_balance_mismatches`: آخر رصيد مسجل لا يطابق رصيد المنتج الحالي.
- `healthy`: صحيح فقط عندما تكون المؤشرات الثلاثة صفرًا.

الفحص قراءة فقط ولا يصحح البيانات تلقائيًا. أي اختلاف يحتاج مراجعة مصدر الحركة
والشفت والعملية المرتبطة قبل أي إصلاح.

## النشر والقبول

```bash
php artisan migrate
php artisan optimize:clear
npm run test:mobile-inventory
```

اختبر مالكًا ومحاسبًا، رفض متجر غير مصرح، pagination، فلاتر يوم العمل، ومنتجًا
عاديًا وطقمًا ورولًا. قارن آخر حركة ورصيد المنتج يدويًا على عينة قبل اعتماد API.

## الرجوع

المسارات للقراءة فقط والفهارس توسعية. يمكن تعطيل ميزتي `inventory_read` و
`inventory_integrity` وإزالة routes مؤقتًا دون تغيير بيانات المخزون.

# تدقيق دفعة تأكيدات خمسة أنظمة

> حالة التنفيذ: وُحّدت التأكيدات المضمّنة في Blade عبر عقد `data-ui-confirm` مع الحفاظ على نصوص التحذير والمسارات وشروط ظهور الإجراءات.

## الأنظمة المشمولة

### 1. إدارة الموظفين والمديونيات

- نُقل تأكيد تصحيح المديونية إلى النموذج نفسه بدل `onclick` على زر الحفظ.
- نُقل تحذير تحديث الموظف، بما فيه أثر تغيير المتجر الموضح للمستخدم، دون حذف أو اختصار.
- نُقل تأكيد الحذف النهائي من صفحة سلة الموظفين إلى الحوار المشترك.

### 2. الاستهلاك الداخلي

- وُحد تأكيد حذف عملية الإضافة.
- وُحد تأكيد حذف استهلاك المحاسب مع إبقاء عبارة استرجاع المخزون واضحة.
- وُحد تأكيد الحذف النهائي من سلة الاستهلاك.

### 3. أوامر الشراء

- نُقل تأكيد إلغاء الطلبية من `onsubmit` المضمّن إلى عقد الحوار المشترك.
- بقي مسار الإلغاء وحالة ظهور الإجراء وطلب `POST` دون تغيير.

### 4. إدارة الشفت الثاني

- نُقل تأكيد إعادة تفعيل الشفت الثاني إلى الحوار المشترك.
- لم تتغير حالة المنع أو شرط السماح بإعادة التفعيل أو المسار المستعمل.

### 5. التنبيهات الإدارية للموظفين الموقوفين

- نُقل تحذير إنهاء الموظف وحساب المحاسب المرتبط إلى الحوار المشترك.
- بقي نص مراجعة الالتزامات، وطريقة `DELETE`، والمسار، والإجراء البديل للمسافر كما هي.

## حدود الأمان

- لم يُعدل Controller أو Route أو Model أو Migration أو Service.
- لم تتغير طريقة قراءة البيانات أو كتابتها، ولم تتغير أي نتيجة مالية أو مخزنية أو صلاحية.
- لم تُحذف تحذيرات العمليات الحساسة؛ تغير مكان تشغيل التأكيد فقط من JavaScript داخل Blade إلى الوحدة المركزية الموجودة.
- يستخدم العقد SweetAlert عند توفره، ويستخدم احتياط المتصفح من الوحدة المركزية فقط عند عدم توفره.

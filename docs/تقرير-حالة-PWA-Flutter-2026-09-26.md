# تقرير حالة مشروع PWA وFlutter

**تاريخ التقرير:** 2026-09-26
**نقطة الأساس:** الالتزام `7954f2b`
**الهدف:** توثيق ما أُنجز، وما بقي، وحدود الأمان، والخطوة التنفيذية التالية دون اعتبار قاعدة الجهاز بديلًا عن قاعدة Laravel.

---

## 1. الملخص التنفيذي

وصل المشروع إلى مرحلة متقدمة في تأسيس PWA وBackend مشترك لتطبيق Flutter المستقبلي. أصبح النظام يملك PWA قابلة للتثبيت، وAPI v1، وجلسات أجهزة قابلة للإبطال، وتجديد Tokens، وإشعارات Push، وIdempotency، وتخزين مسودة الجرد في IndexedDB، وواجهات قراءة لعدد من الأنظمة التشغيلية.

لم يبدأ تطبيق Flutter نفسه بعد، ولم تُفتح عمليات الكتابة المالية أو المخزنية الحساسة عبر Mobile API. Laravel وقاعدة البيانات الأساسية يظلان المصدر الوحيد للحقيقة.

| المسار | الحالة الحالية |
| --- | --- |
| PWA الأساسية | مكتملة برمجيًا وتحتاج استمرار اختبارات الأجهزة الفعلية |
| API v1 | أساس موحد ومنفذ |
| جلسات الأجهزة | منفذة كأساس آمن |
| الإشعارات | منفذة كأساس وتحتاج اختبار Push فعلي على Staging |
| IndexedDB | منفذة لمسودة الجرد |
| APIs القراءة | منفذة للمنتجات والمخزون والشفت والمبيعات والتوريد والنقل |
| APIs الكتابة الحساسة | مغلقة عمدًا |
| Flutter | لم يبدأ |
| اختبارات الحمل والمراقبة | لم تكتمل |
| مركز الهوية والتصميم | لم يكتمل |

**التقدم التقديري نحو الهدف الكامل:** بين 45% و50%. هذه نسبة تخطيطية وليست إعلان جاهزية للإنتاج.

## 2. المبادئ التي تحكم التنفيذ

1. قاعدة Laravel الحالية هي المصدر الوحيد للحقيقة.
2. لا تستخدم قاعدة الإنتاج في التطوير أو الاختبارات.
3. لا تنفذ عمليات `migrate:fresh` أو `db:wipe` على البيانات الحقيقية.
4. IndexedDB وSQLite مستقبلًا مخصصتان للـCache والمسودات والبيانات المحدودة، وليستا نسخة مستقلة من النظام.
5. لا تعتمد عملية مالية أو مخزنية Offline.
6. لا تستخدم Last Write Wins في المخزون أو المال.
7. كل كتابة قابلة لإعادة الإرسال تحتاج Idempotency ومعاملة وقفلًا وفحص تعارض.
8. لا يضاف منطق أعمال موازٍ داخل Flutter؛ التطبيق يستدعي خدمات Laravel.
9. تنفذ الخطة نظامًا بعد نظام، لا كتغيير شامل لكل المشروع دفعة واحدة.

## 4. ما تم إنجازه في البنية المشتركة

### 4.1 API v1

تم إنشاء عقد API موحد يتضمن:

- Envelope ثابت للنجاح والخطأ.
- `api_version`.
- `request_id`.
- أخطاء Validation موحدة.
- منع Cache المشترك والحساس.
- Rate Limiting.
- Cursor Pagination في القوائم الكبيرة.
- عزل المتاجر.
- Abilities حسب وظيفة المسار.

### 4.2 مصادقة الأجهزة

تم تنفيذ:

- Access Token مخزن كبصمة Hash.
- Refresh Token مع Rotation.
- ربط الجلسة بـ`device_uuid`.
- تسجيل اسم الجهاز والمنصة وإصدار التطبيق.
- إبطال الجهاز الحالي أو بقية الأجهزة.
- حد أعلى للأجهزة.
- حد أدنى لإصدار التطبيق.
- التحقق من حالة الحساب والمتجر والاشتراك في كل جلسة.

### 4.3 Idempotency

تم إنشاء أساس دائم يمنع تكرار أثر الطلب عند إعادة الإرسال، ويشمل:

- عزل المفتاح حسب الحساب.
- بصمة للطريقة والمسار والبيانات.
- إعادة الاستجابة المكتملة.
- رفض إعادة استخدام المفتاح لبيانات مختلفة.
- مهلة للطلب المتوقف.
- تنظيف السجلات المنتهية.

العقد مطبق حاليًا على تعديلات منخفضة المخاطر مثل قراءة/إخفاء الإشعارات وتسجيل Push، ولم يطبق بعد على البيع أو الاعتمادات المخزنية.

### 4.4 الصيانة المجدولة

توجد مهام مجدولة لـ:

- تنظيف الإشعارات القديمة.
- تنظيف مفاتيح Idempotency.
- تنظيف جلسات الأجهزة المنتهية.

تحتاج بيئة الاستضافة إلى Scheduler فعال وQueue worker للإشعارات الخارجية.

## 5. حالة PWA

### المنجز

- Manifest عربي وRTL.
- `display: standalone`.
- أيقونة SVG نصية دون ملفات PNG ثنائية.
- Service Worker بإصدار بناء.
- Offline shell عامة.
- Network First للتنقل.
- Cache للملفات العامة الثابتة فقط.
- منع Cache لمسارات الإدارة والمالك والمحاسب وAPI.
- منع تخزين طلبات الكتابة.
- دورة تحديث تنتظر حفظ المسودات قبل تفعيل النسخة الجديدة.
- تنظيف Caches القديمة.
- بوابات فحص للعقد والنشر والمتصفح.

### الحدود الحالية

- Offline shell لا تعني أن العمليات المالية تعمل دون اتصال.
- لا يوجد Background Sync للعمليات الحساسة.
- لا يوجد Outbox للبيع أو الاعتماد أو النقل.
- يجب استمرار اختبار PWA على أجهزة Android ضعيفة ومتوسطة، وليس الاعتماد على HTTP checks فقط.

## 6. التخزين المحلي وOffline

### المنجز لمسودة الجرد

- قاعدة IndexedDB باسم `carled-client`.
- مستودع `drafts`.
- عزل حسب نوع الحساب والمعرف والمتجر والجلسة.
- ترحيل مسودة `localStorage` القديمة.
- حد 256 KiB للمسودة.
- حد 50 مسودة لكل حساب.
- تنظيف حسب العمر.
- حذف موجّه عند تسجيل الخروج.
- مقارنة `serverVersion` قبل الاستعادة.
- انتظار حفظ المسودة قبل تحديث PWA.

### المسموح محليًا

- مسودات غير معتمدة.
- بيانات مرجعية محدودة.
- فلاتر العرض.
- Metadata للمزامنة المستقبلية دون أسرار.

### الممنوع اعتماده Offline

- البيع النهائي.
- التحصيل أو المصروف.
- إغلاق الشفت.
- قبول أو رفض النقل.
- اعتماد الجرد.
- تعديل المخزون.
- اعتماد أو حذف طلب توريد.

## 7. حالة الأنظمة

### النظام 1: المصادقة والمستخدمون والصلاحيات

**منجز كأساس:** جلسات الأجهزة، Refresh Token، الإبطال، عزل المتاجر، Rate Limiting، Abilities، وفحص حالة الحساب والمتجر والاشتراك.

**المتبقي:** اختبارات Staging كاملة، سياسة إبطال الجلسات بعد تغيير كلمة المرور، ومركز أمني للأجهزة.

### النظام 2: الإشعارات ومركز النشاط

**منجز كأساس:** إشعارات داخلية، عزل المستلمين، القراءة والإخفاء، API، Push، ربط الجهاز، Queue، Retry، Timeout، تنظيف، وصفحة صيانة إدارية.

**المتبقي:** اختبار OneSignal الحقيقي على Staging، Deep Links، مراقبة `failed_jobs`، وقياس الإرسال واسع النطاق.

### النظام 3: المنتجات والأقسام والبحث

**منجز للقراءة:** الأقسام، المنتجات، التفاصيل، البحث والباركود، الفلاتر، Cursor Pagination، مزامنة تزايدية وTombstones، دون كشف التكلفة.

**المتبقي:** قياس البحث العربي على بيانات فعلية، مراجعة `EXPLAIN`، وتجربة الباركود في Flutter.

### النظام 4: المخزون وحركاته

**منجز للقراءة:** الملخص، الحركات، الفلاتر، الأرصدة السالبة، وفحص مطابقة آخر حركة مع الرصيد، دون API عامة لتعديل المخزون.

**المتبقي:** تشغيل فحص السلامة على Staging، مراجعة أي فروقات قديمة بعد موافقة، واختبارات الضغط.

### النظام 5: الشفت ويوم العمل

**منجز للقراءة:** الشفت الحالي، سجل الإقفالات، الأيام الناقصة، ويوم العمل، باستخدام الخدمة المركزية الحالية.

**المتبقي:** فتح وإغلاق الشفت، موازنة الكاش، Idempotency، القفل، واختبار التعارض.

### النظام 6: البيع والفواتير

**منجز للقراءة:** قائمة المبيعات، التفاصيل، البنود التاريخية، الفاتورة، ملخص يوم العمل، والعزل حسب المتجر دون كشف الربح أو التكلفة.

**المتبقي:** سلة البيع، الدفع والتحصيل، الخصومات والضرائب، الفاتورة، الباركود، الطباعة، Idempotency، وفحص الرصيد.

### النظام 7: طلبيات التوريد

**منجز للقراءة:** القائمة، ملخص الحالات، التفاصيل، البنود، التكلفة، الأحداث، أسباب الرفض والعكس، ويوم عمل الاعتماد.

**المتبقي:** الإنشاء، التعديل، الإرسال، الاستلام، مراجعة المالك، الاعتماد المخزني، الرفض، الإرجاع، PDF، وIdempotency.

### النظام 8: النقل المخزني

**منجز للقراءة:** القائمة، الملخص، التفاصيل، الوارد والصادر، مطابقة المنتجات، الوحدات، التكلفة، ويوم عمل الإرسال أو الإجراء.

**المتبقي:** مسودة الهاتف، الإرسال، القبول، الرفض، الإلغاء، إعادة فحص الرصيد، القفل، Idempotency، ومعالجة التعارض.

### النظام 9: الجرد

**منجز جزئيًا:** الحفظ الجماعي في الويب، مسودة IndexedDB، العزل، الاستعادة، والتحقق من إصدار الخادم.

**المتبقي:** Mobile API للجلسات والبنود، الحفظ المرحلي، نسخة السجل، إرسال النتائج، مراجعة المالك، إعادة العد، والاعتماد الآمن.

### النظام 10: الموظفون والمحاسبون

**الحالة:** لم يبدأ Mobile API الخاص به.

**المطلوب:** القراءة حسب الصلاحية، حالة الحساب والمتجر، السلف والديون حسب الموجود، نقل الحساب، وسجل العمليات مع حماية الخصوصية.

### النظام 11: المصروفات والاستهلاك والعمليات المالية المساندة

**الحالة:** لم يبدأ Mobile API الخاص به.

**المطلوب:** القراءة والملخصات، ثم الكتابة الآمنة المرتبطة بالشفت ويوم العمل، Idempotency، والمرفقات، مع منع الاعتماد Offline.

### النظام 12: التقارير وPDF

**منجز جزئيًا:** توجد تقارير وPDF في الويب، ومنها تقرير النقل.

**المتبقي:** فهرس تقارير عبر API، روابط تنزيل مؤقتة، حالة تجهيز التقرير، Queue للتقارير الثقيلة عند الحاجة، ومشاركة Flutter.

### النظام 13: الاشتراكات والإدارة والأمن

**منجز جزئيًا:** فحص الاشتراك والحساب والمتجر، حد الأجهزة، الحد الأدنى للإصدار، Rate Limiting، Request ID، والتنظيف المجدول.

**المتبقي:** مركز أمني، سجل تدقيق للأجهزة، Feature Flags إدارية، Kill Switch، وسياسة إيقاف الإصدارات القديمة.

### النظام 14: الهوية ومركز التحكم

**منجز جزئيًا:** هوية الويب وPWA والألوان الأساسية وأيقونة SVG.

**المتبقي:** Design Tokens مشتركة مع Flutter، Preview/Publish/Rollback، سجل تغييرات، وعقد JSON للهوية.

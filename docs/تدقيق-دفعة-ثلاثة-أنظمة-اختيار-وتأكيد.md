# تدقيق دفعة ثلاثة أنظمة: اختيار المستلمين وتأكيد أوامر الشراء

> حالة التنفيذ: استُخرجت واجهتا اختيار المستلمين وتأكيدات قائمة أوامر الشراء إلى وحدات مشتركة دون تعديل الاستهداف أو البيانات أو منطق الطلبات.

## 1. إرسال الإشعار الداخلي

- نُقل منتقي المستخدمين والمحاسبين إلى `admin-notification-recipients.js`.
- بقي الحقل `target_ids` بصيغة JSON وبالعقد الحالي نفسه دون تغيير.
- أصبحت شارات المستلمين تُبنى بعناصر DOM و`textContent` بدل `innerHTML`.
- بقي اختيار الكل والإلغاء والبحث والتصفية وتغيير الفئة المستهدفة بالسلوك نفسه.

## 2. إرسال OneSignal

- تستخدم شاشة OneSignal منتقي المستلمين المشترك نفسه.
- بقي مسار الإرسال وخيارات الجمهور وعقد `target_ids` دون تغيير.
- لم تتغير إعدادات OneSignal أو الأسرار أو الإرسال أو الكتابة في قاعدة البيانات.

## 3. تأكيدات قائمة أوامر الشراء

- نُقلت تأكيدات الإلغاء والحذف النهائي إلى `data-ui-confirm`.
- أضيف `data-ui-confirm-busy` لتعطيل زر العملية بعد الموافقة ومنع النقر المزدوج.
- حُذفت دالة `handleSecureSubmit` المحلية المكررة.
- بقيت المسارات وطرق `POST` و`DELETE` ونصوص التحذير كما هي.

## حدود الأمان

- لم يُعدل Controller أو Route أو Model أو Migration أو Service أو استعلام.
- لم تتغير هوية المستلم أو آلية الاستهداف أو قراءة وكتابة الإشعارات.
- لم تتغير أوامر الشراء أو المخزون أو الصلاحيات أو أي بيانات مالية.
- لم يُعدل مستند قرارات الإشعارات لأن هذه الدفعة لا تعتمد قرارًا جديدًا ولا تغير سلوك الخادم.

# سياسة أمان قاعدة البيانات عند تشغيل الاختبارات

هذا المشروع يحتوي على اختبارات تستخدم `RefreshDatabase`، وهذا السلوك يعيد تجهيز قاعدة البيانات المستخدمة في بيئة الاختبار.
لذلك يجب عدم تشغيل الاختبارات على قاعدة بيانات الإنتاج أو قاعدة بيانات تحتوي على بيانات حقيقية.

## الوضع الافتراضي الآمن

ملف `phpunit.xml` يضبط الاختبارات على قاعدة SQLite داخل الذاكرة ويستخدم `force="true"` حتى لا تستطيع متغيرات البيئة المحلية مثل إعدادات `.env` أو متغيرات الطرفية استبدال إعدادات الاختبار الآمنة:

```xml
<!-- هذه الإعدادات مقصودة لحماية قاعدة البيانات الحقيقية عند تشغيل الاختبارات -->
<env name="DB_CONNECTION" value="sqlite" force="true"/>
<env name="DB_DATABASE" value=":memory:" force="true"/>
```

بهذا الوضع، كل بيانات الاختبار تكون مؤقتة داخل الذاكرة ولا تلمس قاعدة البيانات الحقيقية، حتى لو كانت بيئة التطوير مضبوطة على MySQL أو قاعدة خارجية. معنى ذلك أنه لا يوجد خوف على بيانات قاعدة البيانات الحقيقية عند تشغيل كل الاختبارات طالما يتم تشغيلها عبر إعدادات PHPUnit الحالية ودون تفعيل خيار التجاوز اليدوي.

## الهيكل الموحّد بدل migrations الإنتاجية

اختبارات `RefreshDatabase` لا تشغّل سجل migrations الإنتاجي التاريخي كاملًا. يوجّه
`tests/TestCase.php` عملية `migrate:fresh` إلى `database/migrations/testing`، ثم يحمل هيكل SQLite
النهائي من `database/testing/sqlite-schema.sql`. هذا الهيكل بلا بيانات ومشتق من مرجع MySQL المرفق،
مع إضافة أحدث جداول وحقول المشروع.

هذا الفصل مقصود: migrations الإنتاج تبقى لترقية MySQL/MariaDB، بينما الهيكل الاختباري ينشئ الحالة
النهائية مباشرةً على SQLite. عند إضافة جدول أو عمود جديد يجب تحديث الهيكل الاختباري واختبار عقده؛
وإلا ستكشف الاختبارات غياب العنصر الجديد بدل أن تتوقف في منتصف سجل migrations تاريخي طويل.

## طريقة تشغيل الاختبارات

من بيئة التطوير أو CI شغّل:

```bash
php artisan test
```

أو:

```bash
vendor/bin/phpunit
```

عند بداية كل اختبار ستظهر رسالة توضح قاعدة البيانات المستخدمة، مثل:

```text
[اختبارات] قاعدة البيانات المستخدمة: DB_CONNECTION=sqlite, DB_DATABASE=:memory:
[اختبارات] الوضع آمن: سيتم استخدام قاعدة SQLite داخل الذاكرة فقط.
```

## الحماية من قاعدة البيانات الحقيقية

ملف `tests/TestCase.php` يحتوي على حماية تمنع تشغيل الاختبارات إذا لم تكن قاعدة البيانات هي:

```text
DB_CONNECTION=sqlite
DB_DATABASE=:memory:
```

إذا كانت الإعدادات تشير إلى MySQL أو قاعدة بيانات حقيقية، سيتم إيقاف الاختبارات برسالة تحذيرية قبل تشغيلها.

## التجاوز المسموح فقط لقاعدة اختبار منفصلة

إذا كان لديك قاعدة اختبار منفصلة وليست قاعدة إنتاج، يمكن التجاوز مؤقتًا عبر:

```bash
ALLOW_REAL_DATABASE_TESTS=true php artisan test
```

لا تستخدم هذا الخيار على السيرفر الحقيقي أو قاعدة بيانات الإنتاج.

## أوامر ممنوعة على قاعدة البيانات الحقيقية

لا تنفذ أيًا من الأوامر التالية على قاعدة بيانات حقيقية:

```bash
php artisan migrate:fresh
php artisan migrate:refresh
php artisan migrate:reset
php artisan migrate:rollback
```

الأمر المقبول لتطبيق migrations الجديدة فقط هو:

```bash
php artisan migrate
```

ويفضل دائمًا أخذ نسخة احتياطية قبل تشغيله على قاعدة تحتوي بيانات حقيقية.

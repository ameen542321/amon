# تدقيق نظام المخزون قبل التنفيذ

> هذه الوثيقة هي بوابة الدفعة الكاملة لنظام المخزون. لم تنفذ أثناء هذا الجرد أي كتابة أو تعديل لقاعدة البيانات أو الحسابات أو الوحدات.

## 1. نطاق النظام الكامل

لا يقسم نظام المخزون إلى إصلاحات صفحات منفردة. النطاق المترابط هو:

1. `resources/views/user/stores/products/stock/index.blade.php`: إدارة رصيد منتج وحركاته.
2. `resources/views/user/stores/products/audit.blade.php`: قائمة الجرد وحالات الأحمر والأصفر والأخضر.
3. `app/Http/Controllers/ProductStockController.php`: العرض، تأكيد الجرد، الزيادة، والنقص.
4. أجزاء الجرد في `app/Http/Controllers/ProductController.php`: قائمة الجرد وملخص حالاته.
5. `app/Models/Product.php`: تطبيع الوحدات، الزيادة، النقص، ودورة الجرد.
6. `app/Models/StockMovement.php`: حفظ الحركة والكمية المطلوبة والرصيدين.
7. إعدادات دورة الجرد في `app/Models/Store.php` و`app/Http/Controllers/StoreController.php`.
8. مسارات المخزون والجرد في `routes/user.php`.
9. اختبارات المخزون والوحدات وحركاته الموجودة في `tests/Feature` و`tests/Unit`.

الخدمات والتقارير التي تقرأ المخزون، مثل تقارير المتجر، تدخل في مقارنة النتائج ولا تعدل ضمن الدفعة إلا بموافقة مستقلة.

## 2. عقود المسارات الحالية

| العملية | الطريقة | اسم المسار |
| --- | --- | --- |
| صفحة الجرد | `GET` | `user.stores.products.audit` |
| إدارة مخزون المنتج | `GET` | `user.stores.products.stock` |
| تأكيد الجرد | `POST` | `user.stores.products.stock.audit-confirm` |
| زيادة المخزون | `POST` | `user.stores.products.stock.increase` |
| نقص المخزون | `POST` | `user.stores.products.stock.decrease` |

يمنع تغيير الطريقة أو الاسم أو معاملات `store` و`product` أثناء فصل الواجهة.

## 3. عقود الطلبات

### تأكيد الجرد

- الحقل: `audit_note`.
- اختياري، نص، وبحد أقصى 255 حرفًا.
- يمنع التأكيد عندما تكون `can_confirm` غير متاحة.
- يسجل `InventoryLog` وحركة مخزون صفرية تحفظ الرصيد قبل وبعد دون تغييره.

### الزيادة والنقص

- الحقول الثابتة: `quantity`, `unit_type`, `note`.
- `quantity` موجبة وإلزامية.
- `unit_type` محصور في `unit`, `piece`, `roll`, `meter`, `meters` أو يحدد افتراضيًا في الخادم.
- `note` اختياري وبحد أقصى 255 حرفًا.
- التنفيذ داخل transaction مع `lockForUpdate`.
- النقص يرفض الرصيد الصفري ويرفض الكمية التي تتجاوز المتاح.

## 4. عقود الوحدات التي لا يجوز تغييرها

- المنتج العادي: الوحدة الأساسية `unit`.
- منتج الرول: `roll` يضرب في `roll_length`، و`meter`/`meters` يضاف كما هو.
- منتج الطقم: `piece` يقسم على `items_per_unit`، والطقم الكامل يبقى وحدة كاملة.
- `default` و`normalized` قيمتان مطبعتان لا يعاد تحويلهما.
- قيمة صفر أو قيمة سالبة لا تتحول إلى حركة موجبة.
- `requested_quantity` و`requested_unit_type` يجب أن يحفظا معنى إدخال المستخدم، بينما `quantity` في الحركة تحفظ المقدار المطبع.

## 5. عقود الرصيد والحركة

قبل أي فصل JavaScript أو PHP يجب تثبيت المقارنات التالية:

1. الرصيد قبل الحركة.
2. الكمية المطلوبة ووحدتها.
3. الكمية المطبعة المخزنة.
4. الرصيد بعد الحركة.
5. نوع الحركة `increase` أو `decrease` أو تأكيد الجرد.
6. المستخدم والملاحظة وتاريخ العمل.
7. عدم إنشاء حركة عند فشل التحقق.
8. عدم تنفيذ الطلب مرتين عند النقر المتكرر.

## 6. واجهات الدفعة

### إدارة المخزون

- مراجعة التجاوب على 320 و375 و768 و1366 بكسل.
- توحيد SweetAlert بوصفها النافذة الأساسية مع إبقاء المتصفح احتياطًا.
- الحفاظ على منع السحب عندما يكون الرصيد صفرًا.
- الحفاظ على تعطيل زر الإرسال بعد الموافقة.
- الحفاظ على حقول الوحدة المناسبة للعادي والطقم والرول.
- مراجعة جدول الحركات وعدم تغيير طريقة حساب القيم التاريخية.

### الجرد

- مراجعة البحث وفلتر الحالات والصفحات.
- الحفاظ على تعريف الأحمر والأصفر والأخضر ودورة الجرد الحالية.
- الحفاظ على رابط العودة من إدارة المخزون إلى الجرد عبر `return_to=audit`.
- لا يتحول تأكيد الجرد إلى تعديل مباشر للكمية.

## 7. التكرار والتنظيف المرشح

- سكربت إدارة المخزون يجمع منع عجلة الأرقام وتعطيل الأزرار والتأكيد والرسائل؛ يمكن ربط الأجزاء العرضية بوحدة الحوارات المشتركة.
- لا تنقل شروط الرصيد أو تطبيع الوحدة إلى JavaScript؛ يبقى الخادم والموديل مصدر القرار النهائي.
- لا تحذف التعليقات التي توثق معنى المتر والرول والطقم أو سبب `lockForUpdate`.
- لا تعد أي دالة مخزنية خاملة لمجرد عدم استدعائها من صفحة إدارة المخزون؛ يجب فحص التوريد والبيع والنقل والتقارير أولًا.

## 8. الاختبارات الموجودة والاختبارات الناقصة

الاختبارات الموجودة تشمل صفحة المخزون، ملكية المنتج للمتجر، الزيادة، النقص، رفض تجاوز الرصيد، تطبيع الوحدات، وعرض الحركات.

قبل التنفيذ يلزم إضافة أو تشغيل حالات تغطي:

1. تأكيد الجرد المسموح والممنوع وتكراره في الدورة نفسها.
2. الزيادة والنقص بالرول والمتر والطقم والحبة.
3. النقر المكرر وعدم إنشاء حركتين.
4. بقاء الرصيد دون تغيير عند فشل الطلب.
5. تطابق `requested_quantity` و`requested_unit_type` والرصيدين.
6. منع منتجات مشتريات المالك من المخزون والجرد.
7. الرجوع إلى الجرد بعد العملية عند وجود `return_to=audit`.

## 9. بوابة الموافقة قبل التنفيذ

الجرد والاختبارات التي لا تكتب بيانات مسموحة في بيئة اختبار معزولة. أما أي تعديل في `ProductStockController` أو دوال المخزون في `Product` أو `StockMovement` أو إعدادات دورة الجرد أو آلية قراءة/كتابة البيانات، فيتطلب موافقة صريحة مستقلة قبل التنفيذ.

الدفعة التنفيذية التالية، بعد الموافقة، تنفذ نظام المخزون كاملًا في مرور واحد: CSS وJavaScript وPHP والاختبارات والمقارنة، ولا تغير معادلة أو وحدة أو قيمة مخزنة ضمن عملية التنظيم.

## 10. تنفيذ فصل JavaScript العرضي للنظام كاملًا

نُفذت الطبقة العرضية الآمنة لواجهتي إدارة المخزون والجرد في مرور واحد:

- أنشئ ملف واحد واضح `resources/js/features/store-products/inventory-system.js` وحُمّل من `app.js` مرة واحدة.
- نقل سكربت إدارة المخزون حرفيًا من Blade: منع عجلة الأرقام، منع الإرسال المتكرر، تعطيل الأزرار، منع السحب عند الرصيد الصفري، SweetAlert الأساسي، ونافذة المتصفح الاحتياطية.
- أضيف `data-inventory-system` إلى صفحة إدارة المخزون و`data-inventory-audit` إلى صفحة الجرد لتثبيت حدود النظام.
- حذف وسم السكربت التشغيلي كاملًا من صفحة إدارة المخزون.
- لم يتغير أي route أو field أو نص شرط أو قيمة `data-current-stock` أو توقيت إرسال النموذج بعد التأكيد.
- روجع PHP الخاص بالنظام ولم ينقل أو يعدل لأن مصدر الرصيد والتطبيع والحركات يتطلب اختبارات PHP عاملة وموافقة مستقلة.
- لم يحتج النظام إلى CSS جديد؛ بقيت المكونات المركزية الحالية دون تعديل.

لم تمس هذه الخطوة `ProductStockController` أو `Product` أو `StockMovement` أو قاعدة البيانات. لا تعد الدفعة مغلقة نهائيًا قبل تشغيل اختبارات PHP المتخصصة والمراجعة اليدوية على قاعدة اختبار معزولة.

## 11. نتيجة مرور التنظيف الإلزامي

- حذف تخزين `button.dataset.originalText` لأن القيمة لم تكن تقرأ أو تستخدم لاستعادة الزر في أي مسار.
- أبقيت علامة `data-confirmed` لأنها تمنع اعتراض الإرسال المؤكد مرة ثانية.
- أبقيت `data-disable-on-submit` و`data-block-when-empty` لأنهما عقدان مستخدمان فعليًا في الوحدة وفي فحص الهوية.
- أبقيت تعليقات تطبيع الوحدات و`lockForUpdate` لأنها توثق سلوكًا مخزنيًا حساسًا وليست تعليقات قديمة.

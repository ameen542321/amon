# تدقيق نظام صفحات الأخطاء

## 1. النطاق

- 403: منع الوصول.
- 404: الصفحة غير موجودة.
- 419: انتهاء الجلسة.
- 500: خطأ الخادم.
- منع الوصول العام.
- إيقاف المتجر.

## 2. الدمج والتنظيف

- دمج الهيكل المتكرر للصفحات الست في مكوّن واحد `resources/views/components/error-page.blade.php`.
- بقي كل ملف خطأ مسؤولًا عن الرمز والعنوان والرسالة والإجراءات الخاصة به فقط.
- حذف تكرار وثيقة HTML وVite والبطاقة والأيقونة والتخطيط من الملفات الستة.
- استبدلت روابط `javascript:history.back()` بأزرار تستخدم عقد `data-history-back` المشترك.
- استبدل رابط `javascript:location.reload()` في 419 برابط آمن إلى عنوان الصفحة الحالي.
- لا يوجد JavaScript أو CSS مضمن، ولم ينشأ ملف JavaScript جديد.

## 3. التجاوب والوصول

- أصبحت البطاقة تستخدم padding أخف على الجوال وتعود إلى الحجم الأكبر ابتداءً من `sm`.
- أصبحت الإجراءات عمودًا واحدًا بعرض كامل على الجوال، ثم صفًا مرنًا على الشاشات الأكبر.
- حافظت رسائل الأخطاء على التفاف النصوص الطويلة.
- أصبحت أيقونة الحالة زخرفية معلّمة بـ`aria-hidden`، بينما يبقى العنوان النصي هو وصف الخطأ الأساسي.
- تستخدم الصفحات الوضع المظلم الافتراضي ومدخل Vite المركزي.

## 4. العقود المحفوظة

- لم تتغير رموز الأخطاء أو عناوينها أو روابط الصفحة الرئيسية وتسجيل الدخول.
- لم تتغير Exceptions أو Middleware أو Controllers أو Routes.
- لم تتغير صلاحيات الوصول أو الجلسات أو قاعدة البيانات.
- لم يعدل ملف الهوية البصرية أو `resources/css/app.css`.

## 5. مراجعة القبول

1. فتح كل صفحة على 320 و375 و768 و1366 بكسل.
2. التأكد أن الأزرار عمودية على الجوال ولا تسبب تمريرًا أفقيًا.
3. اختبار زر الرجوع مع وجود صفحة سابقة وعدم وجودها.
4. اختبار تحديث صفحة 419 والتأكد من عدم وجود رابط `javascript:`.
5. اختبار صفحة منع الوصول كضيف وكجلسة `web` دون تغيير منطق الخروج.
6. مراجعة الوضعين المظلم والفاتح والنصوص العربية الطويلة.

# تدقيق وتنفيذ واجهات نظام إدارة المتاجر

## النطاق الكامل

- قائمة المتاجر: `resources/views/user/stores/index.blade.php`.
- إنشاء متجر: `resources/views/user/stores/create.blade.php`.
- تعديل متجر: `resources/views/user/stores/edit.blade.php`.
- سلة المتاجر: `resources/views/user/stores/trash.blade.php`.
- النموذج المشترك والبطاقات والمكونات داخل `resources/views/user/stores/includes`.

## الإصلاحات

- أضيف قالب إنشاء المتجر الذي يستدعيه `StoreController` وكان غير موجود، ويستخدم النموذج المشترك نفسه بدل نسخ النموذج.
- أضيف جذر `data-store-management` للقائمة والنموذج والسلة.
- استبدل `onclick="window.history.back()"` بخطاف `data-history-back` في وحدة التنقل الموجودة، دون إنشاء ملف JavaScript جديد.
- صححت التعليقات القديمة التي تصف إصلاحات سابقة بدل وصف وظيفة الكود.
- روجعت كتل PHP في القائمة والنموذج؛ بقيت لأنها تحضر حدود الخطة وخيارات أجور العمل وتؤثر في بيانات حقيقية.
- لم يعدل `app.css` أو Controller أو Model أو قاعدة البيانات.

## التنظيف

- حذف تعليق قديم عن تصحيح اسم حقل السجل التجاري؛ اسم الحقل الحالي مستخدم فعليًا.
- حذف عبارة «تم إصلاح الجريد هنا» واستبدالها بوصف دائم للبطاقة.
- لم تحذف كتلة `$isEdit` لأنها تتحكم فعليًا في route وmethod والعنوان والقيم.
- لم تحذف كتل حدود الخطة لأنها تتحكم في إتاحة إنشاء متجر.
- حذف غلافا `div` بلا كلاس أو سلوك كانا يحيطان بالنموذج دون أثر عرضي أو برمجي.
- حذف التعبير `{{ $isEdit ? ' ' : ' ' }}` من زر الإرسال لأن الفرعين ينتجان قيمة فارغة متطابقة.
- طبعت المسافات المكررة داخل خصائص `class` في ملفات إدارة المتاجر دون تغيير أي اسم كلاس.

## مراجعة القبول

1. فتح قائمة المتاجر ثم صفحة الإنشاء والتأكد من عدم ظهور `View not found`.
2. التأكد أن الإنشاء يستخدم route `user.stores.store` و`POST`.
3. التأكد أن التعديل يستخدم route `user.stores.update` و`PUT`.
4. تجربة زر الرجوع من الإنشاء والتعديل.
5. مراجعة الحقول القانونية والبنكية والشفتات والجرد وخيارات البيع السريع دون حفظ.
6. مراجعة السلة والبطاقات على 320 و375 و768 و1366 بكسل.
7. لا يختبر الحفظ أو الاسترجاع أو الحذف إلا على قاعدة اختبار معزولة.

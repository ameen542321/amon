# تقرير مراجعة جودة التصميم وتجربة الاستخدام

> **تاريخ اليوم وإعداد التقرير:** الأربعاء، 29 يوليو 2026م (`2026-07-29`)
> نوع المراجعة: تدقيق ساكن شامل لطبقة العرض، وعقد الهوية البصرية، وملفات CSS المركزية، دون تشغيل عمليات كتابة أو تغيير بيانات حقيقية.  
> المرجع الحاكم: `docs/الهوية-البصرية-للمشروع.md`.

## الملخص التنفيذي

الحالة الحالية **جيدة ومنظمة على مستوى نظام التصميم، وتحتاج إغلاق فجوات محددة قبل منح اعتماد بصري كامل**.

- توجد قاعدة مركزية ناضجة للأسطح، والنصوص، والحدود، والأزرار، والحقول، والمودالات، والحالات، مع تعريف مستقل ومتناسق للوضعين المظلم والفاتح داخل `resources/css/app.css`.
- التخطيط العام عربي و`RTL` افتراضيًا، والوضع المظلم هو الوضع الابتدائي، كما أن قالب اللوحة يحمّل خط Cairo صراحة.
- التسلسل الهرمي مدعوم بكلاسات مركزية مثل `ui-title` وأحجام نص مقروءة، وتستخدم واجهات العمليات الحساسة عنوان صفحة وحيدًا ثم عناوين أقسام وبطاقات وإجراءات واضحة.
- بوابة الهوية تفحص جميع ملفات Blade البالغ عددها **129 ملفًا**، وتمنع CSS وأحداث DOM المضمّنة في واجهات الويب، والألوان والخطوط المحظورة، وتحمي عددًا كبيرًا من عقود التجاوب والمودالات والأزرار والجداول وإمكانية الوصول. وقد نجح `npm test`، بما فيه عقد الهوية وبناء Vite.
- لم يُرصد تضارب مؤكد في ألوان الهوية، أو استخدام مباشر لأحداث DOM داخل Blade، أو CSS محلي مخالف في صفحات الويب. ظهرت خصائص `style` في تسعة ملفات فقط، وجميعها ضمن استثناءات الطباعة وPDF والبريد المسموحة.
- لا يمكن اعتبار هذه المراجعة اعتمادًا بصريًا نهائيًا للمحاذاة والقص والتباين الفعلي؛ إذ لم تُفتح الصفحات المحمية بحسابات الأدوار ولم تُنفذ مصفوفة المقاسات في متصفح. امتنعت المراجعة عن أي تجربة قد تكتب في قاعدة البيانات الحقيقية.

## قائمة الأخطاء والملاحظات

### P1 — خط Cairo غير مضمون في صفحات المصادقة

- **المكان:** `resources/views/layouts/auth.blade.php` مقارنةً بـ`resources/views/dashboard/app.blade.php`.
- **الحالة الحالية:** CSS يطلب Cairo أولًا، لكن قالب المصادقة لا يحمّل الخط، بينما قالب لوحة التحكم يحمّله من Google Fonts. عند فتح صفحة المصادقة مباشرةً أو فشل وجود الخط محليًا ستنتقل إلى خط النظام البديل، فتختلف القياسات والوزن والهوية بين الدخول واللوحة.
- **الأثر:** اختلاف بصري في أول نقطة اتصال مع النظام، واحتمال تغير التفاف النص وارتفاع الحقول والأزرار.
- **طريقة الإصلاح المقترحة:** توحيد تحميل Cairo في القالبين، والأفضل تحميل أصل محلي واحد من مدخل التطبيق لتفادي اختلاف القوالب والاعتماد على اتصال خارجي. لا يضاف خط بديل جديد ولا يغيّر أي منطق.
- **معيار القبول:** فتح صفحات الدخول والاستعادة والإيقاف من جلسة نظيفة يثبت أن `font-family` المحسوب يبدأ بـCairo في الوضعين وعلى المقاسات الصغيرة.

### P1 — تسميات حقول المصادقة غير مرتبطة برمجيًا بالحقول

- **المكان:** `resources/views/auth/login.blade.php`، و`resources/views/auth/forgot.blade.php`، و`resources/views/auth/reset.blade.php`.
- **الحالة الحالية:** النصوص المرئية موجودة، لكن `label` لا يحمل `for` والحقول المقابلة لا تحمل `id` مطابقًا.
- **الأثر:** النقر على التسمية لا ينقل التركيز إلى الحقل، وتضعف دقة قارئات الشاشة والتنقل السريع، رغم أن الشكل المرئي يبدو صحيحًا.
- **طريقة الإصلاح المقترحة:** إضافة معرف ثابت لكل حقل وربط `label for` به دون تغيير `name` أو `value` أو مسار الإرسال أو التحقق.
- **معيار القبول:** النقر على كل تسمية يركز حقلها، ويعرض فحص المتصفح اسمًا قابلًا للوصول لكل حقل.

### P1 — خيار «تذكرني» يخفي عنصر الإدخال عن لوحة المفاتيح ولا يملك حالة تركيز مرئية

- **المكان:** `resources/views/auth/login.blade.php` مع قواعد `auth-check` في `resources/css/app.css`.
- **الحالة الحالية:** مربع الاختيار يستخدم `class="hidden peer"`، أي `display: none`، ولا توجد قاعدة `peer-focus` أو `focus-visible` ترسم حالة تركيز على البديل المرئي.
- **الأثر:** لا يستطيع مستخدم لوحة المفاتيح الوصول إلى خيار «تذكرني» بصورة موثوقة، وهذا قصور تجربة واستخدام حتى لو كان العنصر متوازنًا بصريًا بالفأرة.
- **طريقة الإصلاح المقترحة:** إبقاء الإدخال قابلًا للتركيز باستخدام نمط إخفاء بصري غير `display:none`، وإضافة حلقة تركيز مركزية للعنصر المرئي عبر كلاس مركزي، مع بقاء النص داخل `label` لتوسيع مساحة النقر.
- **معيار القبول:** يصل مفتاح Tab إلى الخيار، تظهر حلقة تركيز واضحة في الوضعين، وتبدّل Space حالته.

### P1 — الاعتماد البصري عبر المقاسات والأدوار لم يُنفذ بعد

- **المكان:** جميع الواجهات المحمية، وبالأخص الهيدرات، والمودالات، والجداول الطويلة، وصفحات العمليات المالية والمخزنية.
- **الحالة الحالية:** التدقيق الساكن يثبت وجود العقود والكلاسات، لكنه لا يثبت موضع البكسل النهائي، أو عدم قص نص حقيقي طويل، أو تباين حالة مركبة بعد الرسم، أو سلامة القوائم عند بيانات فعلية.
- **الأثر:** تبقى احتمالات ازدحام أو قص أو تمرير أفقي لا تظهر من قراءة المصدر وحدها.
- **طريقة الإصلاح المقترحة:** جولة متصفح **قراءة فقط** بحسابات المالك والمحاسب والمدير، في الوضعين، على `320×568` و`375×667` و`390×844` و`768×1024` و`1366×768` و`1920×1080`. تستخدم قاعدة اختبار معزولة لأي سيناريو يحتاج إرسالًا؛ لا تنفذ كتابة على القاعدة الحقيقية.
- **معيار القبول:** لقطات موثقة لكل قالب رئيسي، وعدم وجود تمرير أفقي للصفحة أو خروج مودال أو اختفاء CTA أو فشل تركيز لوحة المفاتيح.

### P2 — بوابة الهوية قوية لكنها لا تقيس التباين المحسوب آليًا

- **المكان:** `scripts/check-visual-identity.mjs`.
- **الحالة الحالية:** البوابة تثبت قيم الرموز والألوان الممنوعة والعقود البنيوية، لكنها لا تحسب نسب WCAG بين كل لون نص وخلفيته الفعلية، ولا تفحص حالات hover/focus/disabled في متصفح.
- **الأثر:** قد يمر تركيب صحيح اسميًا لكنه ضعيف التباين في سياق معين، خصوصًا النص الهادئ أو الحالات فوق أسطح متداخلة.
- **طريقة الإصلاح المقترحة:** بعد الجولة اليدوية، إضافة اختبار متصفح غير متلف لعينة المكونات المركزية في الوضعين، وقياس التباين للحالات الأساسية والثانوية والخطر والتحذير والمعلومة والتعطيل. هذا تحسين لأداة الفحص فقط ولا يغير البيانات أو المنطق.
- **معيار القبول:** توثيق نسب التباين للنصوص العادية والكبيرة وحالات التركيز، وفشل الاختبار عند النزول عن الحد المعتمد.

## نقاط القوة المثبتة

1. **تسلسل هرمي قابل لإعادة الاستخدام:** `ui-title` للنص الأعلى أهمية، و`ui-text-body` و`ui-text-meta` و`ui-text-caption` للمراتب التابعة، مع مقاسات مركزية تمنع التصغير المفرط.
2. **CTA واضح:** الزر الأساسي بلون العلامة، والتنفيذ الناجح أخضر، والمعاينة معلوماتية، والتحذير أصفر/بني، والحذف أو الإلغاء خطر؛ كما تفرض البوابة الأدوار في الواجهات الحساسة.
3. **توازن ومسافات مركزية:** البطاقات والحقول والأزرار والمودالات تمتلك padding وحدودًا وأنصاف أقطار مركزية، وتستخدم الصفحات تخطيط `flex/grid` وفواصل `gap` بدل تموضع يدوي.
4. **RTL والوضعان:** القالبان الأساسيان يحددان `lang="ar" dir="rtl" class="dark"`، ويملك الوضع الفاتح مجموعة رموز مستقلة بدل قلب جزئي للألوان.
5. **سلامة المودالات:** توجد خلفية وسطح وإغلاق خطر مركزي ومحاذاة وسطية وحدود ارتفاع وتمرير، مع فحوص `aria-label` لأزرار الإغلاق في النطاقات المغطاة.
6. **ضبط الألوان:** لا تسمح البوابة بعائلات الوردي والبنفسجي والبرتقالي المحظورة، وتفصل لون العلامة عن ألوان الحالة.
7. **فصل العرض عن التنسيق:** لا توجد أحداث DOM مضمّنة في Blade، وCSS المحلي ممنوع خارج استثناءات الطباعة وPDF والبريد.

## خطة التحسين والتعديل

### الأولوية الأولى — إصلاح الوصول واتساق الخط في المصادقة

1. توحيد تحميل Cairo عبر أصل مركزي معتمد.
2. ربط تسميات البريد وكلمات المرور بالحقول عبر `for/id` فقط.
3. استبدال إخفاء مربع «تذكرني» بإخفاء بصري قابل للتركيز وإضافة `focus-visible` مركزي.
4. تشغيل بوابة الهوية والبناء، ثم اختبار صفحات المصادقة بلوحة المفاتيح في الوضعين.

هذه الدفعة بصرية وإمكانية وصول فقط؛ لا تغيّر أسماء الحقول أو الطلبات أو المصادقة أو قاعدة البيانات.

### الأولوية الثانية — جولة اعتماد بصري للقراءة فقط

1. تجهيز بيئة اختبار معزولة وحساب لكل دور دون تغيير صلاحيات حقيقية.
2. اختيار شاشة ممثلة لكل قالب: مصادقة، لوحة، قائمة، نموذج، تقرير، جدول، مودال، وحالة فارغة/خطأ.
3. تنفيذ مصفوفة المقاسات والوضعين مع تسجيل لقطات قبل أي إصلاح.
4. ترتيب كل نتيجة وفق: إجراء محجوب، قص/تمرير، تباين/تركيز، محاذاة/مسافات، ثم تحسين تجميلي.
5. عدم إرسال نموذج مالي أو مخزني أو تعديل بيانات إلا على قاعدة اختبار معزولة وبعد نطاق موافق عليه.

### الأولوية الثالثة — تعزيز منع الانحدار

1. إضافة صفحة عرض للمكونات المركزية أو اختبار متصفح لها في المظلم والفاتح.
2. قياس التباين المحسوب وحالات hover/focus/disabled وحجم أهداف اللمس.
3. إضافة فحص عام لارتباط `label` بالحقول القابلة للإدخال، مع استثناءات موثقة فقط.
4. حفظ لقطات مرجعية للقوالب المشتركة بدل إنشاء اختبارات بصرية لكل صفحة.

## حدود المراجعة وقرار الاعتماد

- لم تُعدّل أي واجهة أو CSS أو JavaScript أو منطق مالي أو مخزني أو صلاحيات.
- لم تُقرأ أو تُكتب أو تُحذف أي بيانات، ولم تُنفذ migrations أو عمليات حفظ.
- لم تُراجع الإشعارات كنظام مستقل ولم يُعدل مرجعها؛ ظهور ملفاتها في الحصر العام لا يوسع نطاق المهمة إليها.
- التقرير يوصي بالإصلاحات فقط ولا ينفذها. يلزم اعتماد صاحب المشروع لنطاق دفعة الإصلاح قبل تطبيق أي تحسين إضافي.
- القرار الحالي: **اعتماد بنيوي مشروط، وليس اعتمادًا بصريًا نهائيًا**، إلى أن تغلق ملاحظات المصادقة وتنجح جولة المتصفح عبر المقاسات والأدوار.

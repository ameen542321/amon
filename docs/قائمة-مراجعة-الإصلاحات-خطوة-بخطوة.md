# قائمة مراجعة الإصلاحات خطوة بخطوة

> **الغرض:** مرجع عملي يسجل ما يجب مراجعته من بداية العمل حتى إغلاق كل خطوة.
> **قاعدة الإغلاق:** لا تغلق أي خطوة قبل تسجيل النتيجة في الوضعين المظلم والفاتح وعلى الجوال وسطح المكتب، وتشغيل الفحوص المناسبة.
> **حماية البيانات:** يمنع استخدام بيانات الإنتاج لإجراء تجارب كتابة أو حذف أو تعديل.

## 1. طريقة استخدام القائمة

لكل بند سجل واحدة من الحالات التالية:

- `[ ]` لم يراجع.
- `[x]` نجح.
- `[!]` ظهرت مشكلة وتحتاج إصلاحًا.
- `[-]` لا ينطبق مع ذكر السبب.

وعند ظهور مشكلة سجل:

1. اسم الحساب: مالك، محاسب، أو مدير.
2. اسم الصفحة والرابط.
3. مقاس الشاشة.
4. الوضع: مظلم أو فاتح.
5. خطوات إعادة المشكلة.
6. النتيجة الحالية والنتيجة المطلوبة.
7. لقطة شاشة ورسالة Console إن وجدت.
8. هل العملية قراءة فقط أم كتبت بيانات.

## 2. تجهيز بيئة المراجعة

- [ ] أخذ نسخة احتياطية حديثة من قاعدة البيانات الحقيقية قبل أي تجربة كتابة معتمدة.
- [ ] التأكد أن التجارب الخطرة تستخدم قاعدة اختبار معزولة، لا قاعدة الإنتاج.
- [ ] تسجيل commit الذي بدأت عليه المراجعة عبر `git log -1 --oneline`.
- [ ] التأكد أن `git status --short` لا يحتوي ملفات محلية غير معروفة.
- [ ] تشغيل `npm install` عند تغير `package-lock.json` أو على جهاز جديد.
- [ ] تشغيل `npm run dev` أثناء المراجعة البصرية.
- [ ] فتح Console وNetwork في أدوات المطور.
- [ ] تجهيز حساب مالك ومدير ومحاسب للاختبار دون تغيير صلاحيات حقيقية.

## 3. الفحوص العامة قبل فتح الواجهات

- [ ] `npm test` ينجح بعقد الواجهة وبناء Vite.
- [ ] اختبارات PHP المرتبطة بالنطاق تنجح في بيئة الاختبار.
- [ ] لا توجد أخطاء حمراء في Console عند تحميل لوحة التحكم.
- [ ] لا توجد طلبات مكررة غير متوقعة في Network.
- [ ] لا يظهر وميض عناصر `x-cloak` قبل تهيئة Alpine.
- [ ] الوضع المحفوظ يبقى بعد إعادة تحميل الصفحة.

## 4. مصفوفة المقاسات الإلزامية

كرر المراجعة البصرية الأساسية على:

- [ ] `320 × 568`.
- [ ] `375 × 667`.
- [ ] `390 × 844`.
- [ ] `768 × 1024`.
- [ ] `1366 × 768`.
- [ ] `1920 × 1080` عند توفره.

وفي كل مقاس تحقق من:

- [ ] عدم وجود تمرير أفقي للصفحة.
- [ ] عدم خروج مودال أو قائمة من الشاشة.
- [ ] وضوح النص وعدم تداخله مع الأيقونات.
- [ ] إمكانية الوصول إلى جميع الأزرار باللمس.
- [ ] عدم اختفاء إجراء أساسي.

## 5. مراجعة هيدر وناف بار المالك

### خارج صفحات متجر محدد

- [ ] شعار `Carled` ظاهر كاملًا على الجوال وسطح المكتب.
- [ ] كلمة «متاجري» ظاهرة وثابتة.
- [ ] نافذة «متاجري» متوسطة داخل شاشة الجوال ولا تتجاوز اليمين أو اليسار.
- [ ] أسماء المتاجر الطويلة لا تكسر النافذة.
- [ ] روابط الرئيسية والمبيعات والمنتجات والموظفين والتقارير تعمل للمتجر المختار.

### داخل صفحات متجر محدد

- [ ] اسم المتجر لا يتداخل مع الثيم أو الإشعارات.
- [ ] الاسم الطويل يختصر بصريًا دون كسر الهيدر.
- [ ] قائمة المتجر تفتح داخل الشاشة.
- [ ] تغيير المتجر يبقي المستخدم في القسم الموافق عندما يكون ذلك معتمدًا.
- [ ] روابط المبيعات والفواتير والمنتجات والنقل والمشتريات والموظفين والتقارير تعمل.

### إجراءات الهيدر

- [ ] زر الثيم يعمل ويحفظ الوضع.
- [ ] جرس الإشعارات ظاهر ولا يتداخل مع العناصر.
- [ ] عداد الإشعارات يظهر ويختفي بصورة صحيحة.
- [ ] أيقونة الحساب غير موجودة منفردة في هيدر الجوال.
- [ ] معلومات الحساب وزر تسجيل الخروج موجودان داخل قائمة الهمبرغر على الجوال.
- [ ] قائمة الحساب المكتبية تعمل ابتداءً من `sm`.

## 6. مراجعة هيدر المحاسب

- [ ] الشعار والقائمة والثيم والإشعارات والحساب لا تتداخل على 320px.
- [ ] قائمة الجوال تفتح وتغلق بالنقر وخارجها وبزر Escape.
- [ ] روابط البيع السريع والاستهلاك والمصروف والسحب والغياب والمديونية والبحث والنقل والتحصيل والفواتير تعمل.
- [ ] قائمة الإشعارات لا تتجاوز الشاشة.
- [ ] تسجيل الخروج يعمل.
- [ ] لا تنفذ عملية مالية فعلية لمجرد اختبار الرابط.

## 7. مراجعة هيدر المدير

- [ ] الشعار وزر القائمة والإشعارات والحساب متجاوبة.
- [ ] قائمة الإشعارات لا تتجاوز الشاشة.
- [ ] عدم ظهور رابط إعدادات وهمي.
- [ ] رابط إضافة مستخدم في قائمة الجوال يعمل.
- [ ] تسجيل الخروج يعمل.

## 8. مراجعة الإشعارات الفورية

- [ ] عدم ظهور خطأ عند غياب `window.Echo`.
- [ ] وصول إشعار يزيد العداد مرة واحدة فقط.
- [ ] وصول أول إشعار يزيل رسالة «لا توجد إشعارات».
- [ ] عنوان ورسالة الإشعار يعرضان كنص ولا ينفذان HTML.
- [ ] إشعار المالك لا يحدث قائمة حساب آخر مفتوح في الصفحة.
- [ ] فتح الإشعار ينقله إلى صفحة العرض الصحيحة.

> لا تعدل مرجع قرارات الإشعارات أثناء المراجعة. يحدث فقط عند قول صاحب المشروع «اعتمد» لقرار محدد.

## 9. مراجعة تقرير الطباعة

- [ ] `npm test` لا يعرض خطأ Cairo أو حجم أقل من `10px`، وينجح بعده بناء Vite ضمن الأمر نفسه.
- [ ] تقرير `store-employees-monthly-report` يستخدم Cairo أولًا.
- [ ] النصوص المهمة لا تقل عن `11px`، والفوتر لا يقل عن `10px`.
- [ ] لا تتغير الأرقام أو الأعمدة أو المجاميع.
- [ ] لا ينقطع الجدول أو التوقيعات عند الطباعة/PDF.

## 10. مراجعة إنشاء منتج

### العرض

- [ ] الهيدر وزر الرجوع والعنوان لا تتداخل على 320px.
- [ ] البطاقة تملك هامشًا أفقيًا مريحًا.
- [ ] حقول الطقم عمود واحد على الجوال وعمودان على الشاشة المتوسطة.
- [ ] صف التجزئة عمود واحد على الجوال.
- [ ] زر حذف التجزئة واضح وقابل للمس.
- [ ] الوضعان المظلم والفاتح واضحان.

### السلوك دون حفظ

- [ ] اختيار عادي/رول يظهر الحقول الصحيحة.
- [ ] اختيار قسم التضليل أو التنجيد يحدث الإرشاد الصحيح.
- [ ] بناء اسم منتج التضليل لا يحذف جزءًا مدخلًا.
- [ ] إضافة وحذف عدة خيارات تجزئة يعمل.
- [ ] عجلة الفأرة لا تغير الأرقام دون قصد.

### الحفظ — في قاعدة اختبار فقط

- [ ] أسماء الحقول والـpayload لم تتغير.
- [ ] منتج عادي يحفظ بالقيم المدخلة.
- [ ] منتج رول يحفظ الطول والكمية وخيارات القص كما قبل الإصلاح.
- [ ] منتج طقم يحفظ عدد الحبات وسعر الحبة والحد الأدنى كما قبل الإصلاح.
- [ ] أخطاء validation تظهر كنص آمن وواضح.

## 11. مراجعة تعديل منتج

- [ ] عنوان منتج طويل لا يكسر الهيدر.
- [ ] القيم القديمة تظهر دون تغيير عند فتح الصفحة.
- [ ] `old()` يعيد القيم بعد فشل validation.
- [ ] صفوف التجزئة القديمة والجديدة لها التخطيط نفسه.
- [ ] حذف صف من الواجهة لا يحذف من قاعدة البيانات قبل إرسال النموذج.
- [ ] تغيير الطقم/الحبة لا يعيد تفسير الحركات التاريخية بصمت.
- [ ] حفظ دون تغيير لا يغير الرصيد أو السعر أو الوحدات.

## 12. مراجعة قائمة المنتجات

- [ ] البحث السريع يعرض النتائج الصحيحة.
- [ ] فتح وإغلاق تفاصيل البطاقة يعمل.
- [ ] سجل الأسعار يفتح ويعرض التحميل والفراغ والبيانات بصورة صحيحة.
- [ ] بطاقات المنتجات لا تسبب تمريرًا أفقيًا.
- [ ] الإخفاء والتفعيل والنقل إلى السلة تطلب تأكيدًا واضحًا.
- [ ] قياس عدد الاستعلامات قبل نقل `quickProducts` أو حالة الجرد.

## 13. مراجعة إدارة المخزون

> تنفذ عمليات الكتابة هنا في قاعدة اختبار فقط حتى اعتماد النتائج.

- [ ] عرض الرصيد صحيح للعادي والطقم والرول.
- [ ] الحد الأدنى والوحدة الافتراضية صحيحان.
- [ ] الزيادة تغير الرصيد بالقيمة والوحدة المتوقعة.
- [ ] النقص يمنع عند عدم كفاية الرصيد.
- [ ] الإرسال المكرر ممنوع.
- [ ] رسائل التأكيد تعرض قبل العملية.
- [ ] الرصيد السابق واللاحق في الحركات التاريخية مطابقان لما قبل الإصلاح.
- [ ] حركات المتر والرول والطقم والحبة تعرض بوحدتها التاريخية الصحيحة.
- [ ] الجرد لا يغير أي قيمة قبل التأكيد النهائي.

## 14. مراجعة الملفات والعقود

- [ ] لا يوجد CSS جديد داخل Blade.
- [ ] لا يوجد `style=""` جديد في واجهات الويب.
- [ ] لا توجد أسماء متغيرات جديدة مبهمة.
- [ ] لا توجد دالة أو ملف جديد بلا استخدام مثبت.
- [ ] لا يحذف كود قبل فحص الاستدعاءات الديناميكية.
- [ ] لا تتغير أسماء request أو session أو API أو حقول قاعدة البيانات.
- [ ] كل ملف جديد له مسؤولية واحدة واضحة ومستخدم في أكثر من موضع عند ادعاء المشاركة.
- [ ] جرى بحث أسماء الدوال والمتغيرات المعدلة عبر `rg` وتوثيق عدد مراجعها.
- [ ] حذفت المتغيرات التي تسند ولا تقرأ والكلاسات التي لا يقرأها CSS أو JavaScript بعد إثبات ذلك.
- [ ] حذفت أو صححت التعليقات القديمة من نوع «مضاف» و«مستعاد» و`TODO` المنتهي.
- [ ] لا توجد كتل فارغة أو أسطر مكررة أو imports وملفات بلا استخدام.
- [ ] سجل تقرير النظام العناصر المشكوك بها التي لم تحذف وسبب الإبقاء عليها.

## 15. إغلاق كل خطوة

قبل إغلاق أي خطوة سجل:

- [ ] الملفات المعدلة والجديدة والمحذوفة.
- [ ] ما راجع من CSS وJavaScript وPHP.
- [ ] الفحوص التي نجحت.
- [ ] الفحوص التي تعذرت وسببها.
- [ ] الفروقات البصرية قبل/بعد.
- [ ] الفروقات في payload والنتائج، إن وجدت.
- [ ] تأكيد عدم تعديل قاعدة البيانات أو توثيق الموافقة والنسخة الاحتياطية إن عدلت.
- [ ] تأكيد عدم تعديل ملف الهوية البصرية إلا بموافقة صريحة.
- [ ] خطة الرجوع والـcommit المرجعي.
- [ ] قرار صاحب المشروع: متابعة، إصلاح مشكلة، أو إغلاق الخطوة.
